# 盲测：让模型重建先修关系，能对上多少？

**2026-10-19 实测。这份文档只回答一个问题：这条 loop 值不值得建。**

跑法：`python3 src/probe_llm_prereq.py`（需要能程序化调用模型的通道，见文末阻塞）

---

## 为什么必须先量，不能直接建

现有数据（K12-KGraph）的概念层先修边只覆盖 **30.3%**（5,524/7,938 个知识点没有入边）。
补法要么等上游，要么自己重建。

但自己重建有一个必须先排除的风险 —— **看起来准**。这个项目自己就是活教材：

| 上游数据的问题 | 数字 |
|---|---|
| `prerequisites_for` 里的环 | 2 个二元环 |
| 先修边没有教材原文引用 | 40 / 3,703 |
| **共用同一句教材原文的「证据组」** | 189 组，展开 257 对边 |
| 这些组里真的是环的 | **1 对 → 组级精确率 0.5%** |

一句话可以同时支撑两条互相矛盾的边。**模型生成的边会犯同一类错，而且更像真的** ——
每条都配一段通顺的理由。所以先量，再决定。

---

## 实测：两轮盲测

### 第一轮：我自己当模型（**有污染，数字虚高**）

我给 8 个知识点列前置，31 条。**我已经在这些数据上磨了几个小时，我知道答案**，
所以这一轮只能当上限看，不能当估计。

| 指标 | 数值 |
|---|---|
| 说的名字能在 7,938 个节点里对上 | 25 / 31 = 81% |
| 对上且数据也标了前置 | 5 / 25 = 20% |

### 第二轮：独立子代理（**无污染**）

子代理是**全新会话**，没看过这段对话、没看过数据里的答案。
给它 10 个知识点，只给「名字 + 定义」，不给任何已有边（盲测），要求
「不懂 A 就无法理解 B」，宁缺毋滥。得到 22 条。

**按名字精确重合：0 / 22。**

一条都对不上。逐条人工看过之后，原因不是模型错，是**两套数据的词汇表根本不是一个东西**：

```
梯形的面积   数据说：面积转化方法 / 利用底和高计算面积
           模型说：平行四边形的面积 / 平行四边形的高

凸透镜成像  数据说：像距 / 焦距 / 物距
           模型说：焦点和焦距 / 实像与虚像

质量守恒定律 数据说：化学反应中原子的守恒 / 定量研究
           模型说：化学反应前后原子的种类和数目不变
```

人工逐条判定：

| 判定 | 条数 | 含义 |
|---|---|---|
| AGREE 数据也认 | 3 | 只是写法不同 |
| **RIGHT 数据漏了** | **17** | **纯增量** |
| TYPE 不是一类东西 | 2 | 数据指「方法」节点，模型指「知识」节点 |
| WRONG 说错了 | **0** | — |

**语义站得住 22/22，按名字重合 0/22。**

---

## 三个结论

### 一、真正的发现不是准确率，是 schema 对不上

上游的先修边指向的是**方法/技能**节点（「面积转化方法」「利用底和高计算面积」），
一个合格的知识模型指向的是**知识**节点（「平行四边形的面积」「长方形的面积」）。

两者都能站得住，但**不是同一层东西**。所以：

> **不能把模型输出直接并进现有边集。** 两套边活在两套词汇表里，
> 混起来会得到一个既不可读也不可用的图。

要合并，得先有你说的那个**概念层**——规范概念名、跟教材版本解耦。
概念层一旦有了，「面积转化方法」和「平行四边形的面积」就能分到不同的层，
各自去比。这一步不做，后面全是脏活。

### 二、数据漏标，模型能补

17/22 是纯增量。数据标了 0 前置的那几个知识点（氧化还原反应、液体内部压强、光的折射），
模型 6/6 都给出了站得住的前置 —— 而数据那里是**真空**。

这跟 ISSUE-06 那个 69.6% 对得上：不是这些知识点没有先修，是没标。

### 三、这批数字是乐观上限，不是估计

| 局限 | 说明 |
|---|---|
| 样本 10 个知识点 | 95% 置信区间宽到没法用 |
| 题目偏易 | 平行四边形面积、质量守恒定律都是教科书级的显然题，不是难例 |
| 判定是我手工做的 | 判定人同时也是设计 prompt 的人 |
| 没跑第二轮 | 一轮样本不构成证据 |

真要用这个数字做决策，得跑 **300+ 个随机抽样的知识点、双盲判定**。

## 阻塞：现在没有程序化调用模型的通道

| 尝试 | 结果 |
|---|---|
| `~/.minimax/config.yaml` 里的 `apiKey` | 是占位符 `sk-xxx` |
| 环境里的 `MINIMAX_API_KEY` | 有值，但 `agent.minimax.cn` 这个端点不认（401 token required） |
| `mcode-tools connector tools --keyword llm / model` | 没有 LLM 连接器，只有视频生成 |

`baseURL` 是 `https://agent.minimax.cn/mavis/api/v1/llm/v1` —— agent 运行时的内部代理，
认的是会话 token，不是公开 API key。**7,938 个知识点跑不起批量调用。**

通的办法（任选其一）：
1. 给探针一个能用的公开 API key（MiniMax 开放平台 / 任意兼容端点）
2. 让 runtime 在 config.yaml 里填上真 key
3. 用 `task` 逐批派子代理跑 —— 能跑，但慢，而且每批都有上下文开销

## 建议的 loop（按依赖顺序，不是按野心）

```
第 0 步  概念层规范名表           ← 不做这步，后面全是脏活
        7,938 个名字 → 规范概念 id
        顺带解决「模型在造词」：第二轮 6/22 条
        压根不是节点名（「化学反应中原子种类和数目不变」）

第 1 步  双盲评测 300 个随机知识点  ← 决定要不要往下走
        指标：站得住率 / 造词率 / 与已有边的一致率
        现在这 10 个是 22/22 站得住、0% 名字一致、样本太小

第 2 步  双来源交叉验证
        模型说 A 是 B 的前置 + 数据也这么说 → 双向确认，权重最高
        只有一方说 → 进人工复核队列，不自动并入
        两方都说但粒度不同 → 说明概念层缺了中间层

第 3 步  校验层跑一遍（DAG、环、证据）
        自建的边同样要过现在这套校验。**否则只是把一个不可信的数据集
        换成一个更精致、更不可信的数据集。**

第 4 步  换版本再验一次
        沪教版 / 新教材的知识点进来，同一条依赖边被验第二次
        一次是推测，两次是交叉验证 —— 这是分层设计真正的收益
```
