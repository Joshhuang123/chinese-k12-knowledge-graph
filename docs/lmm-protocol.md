# 盲测重建先修关系 · 协议 v2

给独立子代理的作业说明。每个子代理只跑一个批次，全程不参与批与批之间的讨论，
也看不到别的批次产出的内容 —— **盲测的意义就在这里**。

用法：`src/make_batches.py` 切出 32 批，代理 i 读 `data/lmm-batches/math-NN.json`，
结果写到 `data/lmm-out/math-NN.json`。

## 一、`name` 字段怎么写（最容易错的地方）

`name` 不是描述，是**概念的短名字**。它之后要拿去跟一个已有的知识点词表做精确匹配，
匹配不上就作废。所以必须短、必须是名词、不能是句子。

下面的反例是 v1 协议跑完 2 批之后，从真实失败样本里挑出来的：

| ❌ v1 的写法 | ✅ v2 的写法 |
|---|---|
| 加法就是把两部分合起来 | 加法 |
| 减法就是从总数里去掉一部分 | 减法 |
| 数一数，数出一堆物体有几个 | 数数 |
| 十几是一个十加几个一 | 十几的认识 |
| 把一个数分成两部分或把两部分合成一个数（分与合） | 分与合 |
| 比多少，判断多、少、一样多 | 比多少 |
| 20以内的减法（含十几减几） | 20以内的减法 |
| 注意力能一个一个盯着物体逐个数过去 | 注意力 |

硬性规则：

- **不超过 8 个汉字**
- **不含任何标点**（逗号、顿号、括号全都不行）
- **不含这些字**：就是、意味着、相当于、把、从、能、会、看、想、知、了
- 是一个**名词或名词短语**，不是动作、不是句子

找不到合适的短名时：写最接近的教材常用说法，把 `uncertain` 设成 `true`。
**绝对不要**因为想不到短名就把定义写进 `name` —— 那样这条前置等于丢了。

## 二、判断标准

对**每一条**独立判断：要让一个学生真正理解这个知识点，他必须**先已经会**什么？

唯一判据：

> **「不懂 A，就无法理解 B」** —— 不是「A 排在 B 前面」，不是「A 和 B 有关」，是**真的卡住**。

正例：

- 「两位数减两位数（退位）」的前置是「20 以内的退位减法」—— 真卡。
- 「有余数的除法」的前置是「表内除法」—— 不会整除就没有「余」这个概念。

反例：

- 「认识图形（一）」的前置是「上、下、前、后」—— 同册并列内容，不是前提。
- 「20 以内的进位加法」的前置是「10」—— 「10」是它的一部分，不是前提。
- 「混合运算」的前置是「加减法」—— 太粗，等于说「数学需要数学」。

**宁缺毋滥**。真的没有前置就给 `[]`。乱填比不填有害 —— 填错了会让人以为卡点在那里。

## 三、三类前置，必须分开标

1. `knowledge` —— 一个数学知识。例如「数数」「分与合」「20 以内的退位减法」。
2. `ability` —— **能力/素养，不是数学知识**。例如识字、数量感、生活经验、
   动手操作经验、单位意识、图形直觉。

   这一类特别重要：数据集里**一个 ability 节点都没有**（全是知识点），
   而它恰恰是低年级最主要的卡点来源。认真标。

   同样受 name 规则约束：「识字」「数量感」「生活经验」「单位意识」这种短词才是对的。
   「注意力能一个一个盯着物体逐个数过去」是 v1 的失败写法。

3. `method` —— 方法/策略。例如「分类」「画图表示」「逆推」。

## 四、关于 `existing_prereq`

先**自己判**，再看它。它是参考，不是答案。

- 你认为该有、它没有的 → 照写，这是最值钱的发现。
- 你认为不该有、它有的 → 写进 `dispute`。
- 不要因为它写了你就跟着写，也不要因为它空你就偷懒。

## 五、输出格式

**只输出一个 JSON 数组**，不要解释文字，不要 markdown 围栏。

```json
{
  "id": "math_1a_rjb_cpt1",
  "prereq": [
    {"name": "数数", "type": "knowledge", "why": "不会一一对应地数，读出的数量就是乱的", "uncertain": false},
    {"name": "数量感", "type": "ability", "why": "说不出数的大小就不知道数完得到了什么", "uncertain": false}
  ],
  "dispute": []
}
```

`why` 一句话，讲**断了会怎样**，不要复述 `name`。

## 六、完成标准

- 输入里的每一条**一条都不能漏**，顺序与输入一致
- `why` 具体到「断了会怎样」，不接受「是 B 的基础」这种废话
- 合法 JSON，能被 `json.loads()` 直接解析

## 七、v1 → v2 改了什么，为什么

v1 跑了 2 批（120 个知识点、343 条前置）后验出：

| 指标 | v1 |
|---|---|
| 知识类前置能自动定位到图谱节点 | 38 / 234 = **16%** |
| 接不上的（NEW） | 258 |
| 只对上包含关系，不敢自动连的（CONTAIN） | 20 |
| 与数据集已有的边重合（交叉验证通过） | 15 |

逐条看了 76 个接不上的说法之后，发现**主因不是数据集缺概念，是 `name` 字段写成了句子**。
统计：超长（>10 字）37 个、动词开头 10 个、含「就是/意味着」2 个。

「认识数字1~5」→`数字1到5的认识`这类纯改名的只有 17 条，占不了大头。
真正的头号缺口是「加法就是把两部分合起来」这种把定义当名字写的。

所以 v2 把 name 契约收紧成硬规则，并把上面这张失败对照表直接写进协议。
协议从「请你用普通中文说法」变成「不超过 8 字、不含这些字、不含标点」——
前者模型遵守不了，后者能。
