## R-1　知识点内容召回（让人能自学）

> **提的人**：2026-10-25，一位朋友看见这个项目后很兴奋，想拿它来自学术理化。
> **他说的原话**：「用一套数据库，然后让每个知识点都可以对应召回这个知识图谱里节点对应的那个内容」。

### 要解决什么

现在这个项目是个**图**：能查「谁是谁的前置」「教材第几页有这个概念」。
但它**不能回答「我要学这个概念，读什么、做什么题、先补哪个」**。

对着图谱自学的人现在的路径是：
打开网页 → 搜一个词 → 看它挂了多少条前置 → 点开前置 → 再搜 →
再点前置……**图能告诉你顺序，不能给你教材**。

尤其理化：公式、图、实验结论都在**教材原页**上，
图谱里只有概念的 id 和名字。没有内容召回，自学就还是「拿着目录去找书」。

### 现状盘点（2026-10-25 实测）

内容其实**已经在了**，问题是散在五个平行的文件里，没有统一入口：

| 层 | 覆盖 | 是什么 | 权威性 | 问题 |
|---|---|---|---|---|
| ① 教材原话 | **33.5%**（2,877 个概念） | 教材自己写的定义句 | 最高 | 只覆盖三分之一；OCR 有残缺（句首被切） |
| ② 教材原书公式/图 | **23.4%**（2,012 个概念） | 原页上的公式、图形语义、例题 | 高 | **全量堆着没筛**：一个概念能召回 10 条图描述 + 12 道例题 |
| ③ 图谱定义 | **92.4%**（7,935 个概念） | 数据集里的抽象表述 | 中 | 是「转述」不是「原文」，抽象、偏术语 |
| 至少有一层 | **93.7%** | | | |
| 三层都有 | 18.8% | | | |

另外还有 2.3 万页教材原文（`lessons.jsonl` 12,939 页 + `lessons-sh.jsonl` 9,009 页 + `kx-ocr.jsonl` 1,036 页），
按页存着，**没有跟知识点关联**。

**结论：不是缺内容，是缺「按知识点组织的入口」。**

### 要做成什么样

一个知识点的「自学卡」应该长这样：

```
浮力（沪科版·八下 · 第九章）
├─ 这是什么      教材原话（原文照抄，标出处）+ 图谱定义（转述，标来源）
├─ 怎么算        教材原书上的公式（LaTeX）+ 图形语义（标「据图」）
├─ 练一练        例题（题干 + 答案，去掉重复的）
├─ 先补这些      前置链（已有的「学习路径」面板数据）
└─ 在书里         哪本书 · 哪一节 · 第几页
```

**一次请求，召回这个节点的五个面。**

### 关键约束（做的时候不能忘）

1. **必须分层标来源，不能混为一谈。**
   教材原话是「教材自己说的」，图谱定义是「数据集转述的」——
   页面上现在**已经**分开标（「图谱定义：」前缀），这套口径要保持。
   混起来就是在拿二手货冒充一手。

2. **教材原话要能挑出「定义句」，不是把题干也当定义。**
   现在 `concept-text.jsonl` 里 `hasDefinition` 只对一部分为真，
   剩下的是题干（「看图,用上、下、」）—— 自学时看到的是噪声。

3. **公式/图/例题要排序和截断，不是全量倒出来。**
   一个概念 10 条图描述 + 12 道例题，**先给最相关的 2–3 条**。

4. **不要替用户下结论。**
   「先补这些」只给先修关系链，**不给「你应该先学 X」** ——
   那是模型的主观判断，比教材本身更不可靠。

5. **空内容要明说。**
   6.3% 的概念（544 个）一层内容都没有，召回时要说「这一版没有内容」，
   不能拿相邻概念的内容凑。

### 怎么验算做对了

| 检查项 | 判据 | 实现 | 实测（2026-10-25） |
|---|---|---|---|
| 覆盖率 | 每个概念都能拿到 ≥1 层内容（现在 93.7%） | `check_learn_cards.py` 第 1 组 | 93.1% ✓ |
| 来源分层 | 页面/接口返回的每一段都带来源标记，没有裸文本 | 第 2 组 + `health_check.py` | 0 段裸文本 ✓ |
| 定义句准确 | 抽 50 个概念人工看，定义句必须是「教材自己的定义」而不是题干 | 第 3 组 | 402 条全查，0 条不符 ✓ |
| 噪声控制 | 单次召回的公式 ≤ 6、图描述 ≤ 2、例题 ≤ 5 | 第 4 组 | ✓ |
| 前置链正确 | 「先补这些」跟站点「学习路径」面板的输出**逐条一致** | 第 5 组（**真浏览器里跑站点自己的 JS**） | 抽 200 个，逐条一致 ✓ |
| 冷启动 | 没内容时返回明确的空状态，不是 500，也不是空白 | 第 6 组 | 591 张空卡都带 `emptyNote` ✓ |

**判别力验证**（项目铁律：撤掉修复它会不会红）——
四条检查都实测破坏过：

| 破坏什么 | 检查报什么 |
|---|---|
| 前置链改回读 `graph.json` | ✗ 前置链跟站点面板逐条一致（不一致） |
| 定义句判据去掉「独立词」 | ✗ 143 条定义句的定义对象不符 |
| 图描述不补 `source` | ✗ 114 段缺来源标记 |
| 图描述不过滤 `tier=broad` | ✗ 577 条 broad 图混进来 |

### 实现状态（2026-10-25）

**产出物已就位：**

- `data/learn-cards.jsonl` —— 8,590 张卡，**六个面**齐全
- `data/page-index.json` —— 教材原页段落索引（2,825 个概念 / 6,414 段）
- `src/build_learn_cards.py` —— 生成器
- `src/build_page_index.py` —— 页原文召回（引文反查定位，不用页码换算）
- `src/quote_repair.py` —— 教材原话回原文补全
- `src/check_learn_cards.py` —— 上面那张表的自动化
- `src/check_learn_cards.mjs` —— 浏览器端交叉验证（跑站点自己的 `pathRows()`）
- `docs/agent-data.md` 补了一节（怎么取、字段什么意思、`source` 怎么读）

**六个面与覆盖（实测）：**

| 面 | 覆盖 | 说明 |
|---|---|---|
| `what` | 93.1% | 三级证据强度：教材定义句 4.0% / 教材提及句 10.2% / 图谱定义 92.4% |
| `how` | 22.3% | 教材原书上的公式 + 图形语义 |
| `practice` | 20.7% | 教材例题题干 |
| `prereq` | 95.0% | 直接前置，**不设限量**（跟站点口径一致） |
| `where` | 100% | 哪本书哪一章哪几页 |
| `read` | 32.2% | **教材原页上的那段话** |

**四个实测定位的问题（已修）：**

1. **前置链跟站点对不上** —— 原来只读 `graph.json` 的上游边（3,703 条），
   而站点用的是「上游边 + 自建边（13,461 条）合并过环检测」的结果，
   「浮力」的前置是空的（站点上明明有 3 个）。
   → 改成**直接读站点已构建好的 payload**，不可能对不上。
2. **例题一条都召不回来** —— 视觉层的例题字段叫 `stem`，不叫 `text`。
   按 `text` 取了 8,590 个空。
3. **教材原话答非所问** —— 「电阻」召回的是「内电阻」「电阻率」「电阻箱」。
   引文确实带 `definition` 标记，但**定义的对象不是这个概念**。
   → 改成按「定义对象 == 概念名（且独立成词）」筛，分三级证据强度。
4. **图/公式噪声** —— 视觉层的图描述带 `tier` 分级，
   `broad` 的意思是「只有模型转述里提到了概念名，页面本身跟它没关系」。
   → `broad` 的一律不要。

**一个要说清的更正：** 上一版这里写的「教材原话开头残缺率 9.9%」**用错了判据**。
那个数是按「首字后不接汉字」算的，把「图2-19几种单细胞生物」这种
**图注**也算成了残缺。用可靠判据（句首是黏着字 + 后面接标点）重算：

| | 头部明显残缺 |
|---|---|
| 人教版 5,530 条引文 | 12 条（0.2%） |
| 沪教版 11,151 条引文 | 4 条（0.0%） |

所以**残缺不是主要问题**，主要问题是「召回的对象不对」（第 3 条）。
不过回原文补全还是做了 —— `src/quote_repair.py` 补了 705 条（8.2%），
因为「9.9% 残缺」这个印象已经影响了判断，实际有多少是值得补的得量出来。

**前置链不设限量**：需求清单的「逐条一致」要求跟站点口径相同，
站点那边不截断（实测只有 3 个概念的直接前置超过 8），截了就不一致了。

**页原文不用页码换算**：`lessons.jsonl` 的 `page` 是 PDF 扫描序号，
`concept-text.jsonl` 的 `pages` 是印刷页码，两者不是一套、每册差值不同。
改用**引文反查**定位 —— 概念的原话是教材原文的一段，
在页文本里找这段字就知道它在第几页。

### 还没做的

- **沪教版的原话补全** —— 沪教是页图 OCR，断行位置跟版面无关，
  接回去是瞎接。要补得走视觉模型重读那一页。
- **站点上的学习卡面板** —— 现在只有数据层，站点没接。
  需求清单的 A/B 两条路里选了 B（先做数据层），
  但如果朋友要在网页上点着看，还得做 A。
- **调用接口** —— 现在是「读 jsonl」。
  需求清单里写的「curl / Python 库 / MCP 工具」都还没做，
  等有了实际调用方再定形态（免得做出来没人用）。
### 怎么实现（两条路，倾向 B）

**A. 在现有站点上加一个「学习卡」面板**
- 改动小：payload 已经有 `text` / `vision` / `hard` / `altpos`
- 缺点：**payload 已经在 2.6 MB 预算边缘**，再加内容层会爆；
  而且它服务的是「网页浏览」，不是「批量召回」。

**B. 另建一个内容层 API / 命令行（推荐）**
- 输入一个概念名或 id → 输出结构化的「学习卡」JSON
- 内容从**数据层现算**（`data/*.jsonl`），不进 payload
- 站点页面可以调它，也可以是 `curl` / Python 库 / MCP 工具
- 好处：① 不动页面体积预算 ② 离线可用（agent 直接读文件）
  ③ 能给「批量生成学习卡」留口子

**产出物**（无论 A/B 都要有）：
- `data/learn-cards.jsonl` —— 每个概念一条，五面齐全
- `docs/agent-data.md` 补一节 —— 怎么取、字段什么意思、来源标记怎么读
- 一个校验脚本 —— 把上表那几项判据变成可跑的检查

## R-2　（后续）小学科学的先修关系

R-1 里「先补这些」这一面，小学阶段是空的 ——
上游图谱小学段只有数学（1,182 个概念），物化生一个都没有（上游 issue #10）。

小学科学站（`kx.html`）现在只有**教材序**（编者排的教学先后），
**不是先修关系** —— 页面上是分开标的，虚线边。

给小学生理化做自学，需要真的先修关系。来源码得另立（不能混进上游先修），
工作量比 R-1 大，排在 R-1 后面。
