## R-1　知识点内容召回（让人能自学）

> **提的人**：2026-10-25，一位朋友看见这个项目后很兴奋，想拿它来自学术理化。
> **他说的原话**：「用一套数据库，然后让每个知识点都可以对应召回这个知识图谱里节点对应的那个内容」。

### 要解决什么

现在这个项目是个**图**：能查「谁是谁的前置」「教材第几页有这个概念」。
但它**不能回答「我要学这个概念，读什么、做什么题、先补哪个」**。

对着图谱自学的人现在的路径是：
打开网页 → 搜一个词 → 看它挂了多少条前置 → 点开前置 → 再搜 →
再点前置……**图能告诉你顺序，不能给你教材**。

尤其理化：公式、图、实验结论都在**教材原页**上，
图谱里只有概念的 id 和名字。没有内容召回，自学就还是「拿着目录去找书」。

### 现状盘点（2026-10-25 实测）

内容其实**已经在了**，问题是散在五个平行的文件里，没有统一入口：

| 层 | 覆盖 | 是什么 | 权威性 | 问题 |
|---|---|---|---|---|
| ① 教材原话 | **33.5%**（2,877 个概念） | 教材自己写的定义句 | 最高 | 只覆盖三分之一；OCR 有残缺（句首被切） |
| ② 教材原书公式/图 | **23.4%**（2,012 个概念） | 原页上的公式、图形语义、例题 | 高 | **全量堆着没筛**：一个概念能召回 10 条图描述 + 12 道例题 |
| ③ 图谱定义 | **92.4%**（7,935 个概念） | 数据集里的抽象表述 | 中 | 是「转述」不是「原文」，抽象、偏术语 |
| 至少有一层 | **93.7%** | | | |
| 三层都有 | 18.8% | | | |

另外还有 2.3 万页教材原文（`lessons.jsonl` 12,939 页 + `lessons-sh.jsonl` 9,009 页 + `kx-ocr.jsonl` 1,036 页），
按页存着，**没有跟知识点关联**。

**结论：不是缺内容，是缺「按知识点组织的入口」。**

### 要做成什么样

一个知识点的「自学卡」应该长这样：

```
浮力（沪科版·八下 · 第九章）
├─ 这是什么      教材原话（原文照抄，标出处）+ 图谱定义（转述，标来源）
├─ 怎么算        教材原书上的公式（LaTeX）+ 图形语义（标「据图」）
├─ 练一练        例题（题干 + 答案，去掉重复的）
├─ 先补这些      前置链（已有的「学习路径」面板数据）
└─ 在书里         哪本书 · 哪一节 · 第几页
```

**一次请求，召回这个节点的五个面。**

### 关键约束（做的时候不能忘）

1. **必须分层标来源，不能混为一谈。**
   教材原话是「教材自己说的」，图谱定义是「数据集转述的」——
   页面上现在**已经**分开标（「图谱定义：」前缀），这套口径要保持。
   混起来就是在拿二手货冒充一手。

2. **教材原话要能挑出「定义句」，不是把题干也当定义。**
   现在 `concept-text.jsonl` 里 `hasDefinition` 只对一部分为真，
   剩下的是题干（「看图,用上、下、」）—— 自学时看到的是噪声。

3. **公式/图/例题要排序和截断，不是全量倒出来。**
   一个概念 10 条图描述 + 12 道例题，**先给最相关的 2–3 条**。

4. **不要替用户下结论。**
   「先补这些」只给先修关系链，**不给「你应该先学 X」** ——
   那是模型的主观判断，比教材本身更不可靠。

5. **空内容要明说。**
   6.3% 的概念（544 个）一层内容都没有，召回时要说「这一版没有内容」，
   不能拿相邻概念的内容凑。

### 怎么验算做对了

| 检查项 | 判据 | 实现 | 实测（2026-10-25） |
|---|---|---|---|
| 覆盖率 | 每个概念都能拿到 ≥1 层内容（现在 93.7%） | `check_learn_cards.py` 第 1 组 | 93.1% ✓ |
| 来源分层 | 页面/接口返回的每一段都带来源标记，没有裸文本 | 第 2 组 + `health_check.py` | 0 段裸文本 ✓ |
| 定义句准确 | 抽 50 个概念人工看，定义句必须是「教材自己的定义」而不是题干 | 第 3 组 | 402 条全查，0 条不符 ✓ |
| 噪声控制 | 单次召回的公式 ≤ 6、图描述 ≤ 2、例题 ≤ 5 | 第 4 组 | ✓ |
| 前置链正确 | 「先补这些」跟站点「学习路径」面板的输出**逐条一致** | 第 5 组（**真浏览器里跑站点自己的 JS**） | 抽 200 个，逐条一致 ✓ |
| 冷启动 | 没内容时返回明确的空状态，不是 500，也不是空白 | 第 6 组 | 591 张空卡都带 `emptyNote` ✓ |

### 实现状态（2026-10-25）

**产出物已就位：**

- `data/learn-cards.jsonl` —— 8,590 张卡，**六个面**齐全
- `data/page-index.json` —— 教材原页段落索引（2,825 个概念 / 6,414 段）
- `src/build_learn_cards.py` —— 生成器
- `src/build_page_index.py` —— 页原文召回（引文反查定位，不用页码换算）
- `src/quote_repair.py` —— 教材原话回原文补全
- `src/check_learn_cards.py` —— 上面那张表的自动化
- `src/check_learn_cards.mjs` —— 浏览器端交叉验证（跑站点自己的 `pathRows()`）
- `docs/agent-data.md` 补了一节（怎么取、字段什么意思、`source` 怎么读）

**六个面与覆盖（实测）：**

| 面 | 覆盖 | 说明 |
|---|---|---|
| `what` | 93.1% | 三级证据强度：教材定义句 4.0% / 教材提及句 10.2% / 图谱定义 92.4% |
| `how` | 22.3% | 教材原书上的公式 + 图形语义 |
| `practice` | 20.7% | 教材例题题干 |
| `prereq` | 95.0% | 直接前置，**不设限量**（跟站点口径一致） |
| `where` | 100% | 哪本书哪一章哪几页 |
| `read` | 32.2% | **教材原页上的那段话** |

**四个实测定位的问题（已修）：**

1. **前置链跟站点对不上** —— 原来只读 `graph.json` 的上游边（3,703 条），
   而站点用的是「上游边 + 自建边（13,461 条）合并过环检测」的结果，
   「浮力」的前置是空的（站点上明明有 3 个）。
   → 改成**直接读站点已构建好的 payload**，不可能对不上。
2. **例题一条都召不回来** —— 视觉层的例题字段叫 `stem`，不叫 `text`。
   按 `text` 取了 8,590 个空。
3. **教材原话答非所问** —— 「电阻」召回的是「内电阻」「电阻率」「电阻箱」。
   引文确实带 `definition` 标记，但**定义的对象不是这个概念**。
   → 改成按「定义对象 == 概念名（且独立成词）」筛，分三级证据强度。
4. **图/公式噪声** —— 视觉层的图描述带 `tier` 分级，
   `broad` 的意思是「只有模型转述里提到了概念名，页面本身跟它没关系」。
   → `broad` 的一律不要。

**一个要说清的更正：** 上一版这里写的「教材原话开头残缺率 9.9%」**用错了判据**。
那个数是按「首字后不接汉字」算的，把「图2-19几种单细胞生物」这种
**图注**也算成了残缺。用可靠判据（句首是黏着字 + 后面接标点）重算：

| | 头部明显残缺 |
|---|---|
| 人教版 5,530 条引文 | 12 条（0.2%） |
| 沪教版 11,151 条引文 | 4 条（0.0%） |

所以**残缺不是主要问题**，主要问题是「召回的对象不对」（第 3 条）。
不过回原文补全还是做了 —— `src/quote_repair.py` 补了 705 条（8.2%），
因为「9.9% 残缺」这个印象已经影响了判断，实际有多少是值得补的得量出来。

**前置链不设限量**：需求清单的「逐条一致」要求跟站点口径相同，
站点那边不截断（实测只有 3 个概念的直接前置超过 8），截了就不一致了。

**页原文不用页码换算**：`lessons.jsonl` 的 `page` 是 PDF 扫描序号，
`concept-text.jsonl` 的 `pages` 是印刷页码，两者不是一套、每册差值不同。
改用**引文反查**定位 —— 概念的原话是教材原文的一段，
在页文本里找这段字就知道它在第几页。

### 还没做的

- **沪教版的原话补全** —— 沪教是页图 OCR，断行位置跟版面无关，
  接回去是瞎接。要补得走视觉模型重读那一页。
- **站点上的学习卡面板** —— 现在只有数据层，站点没接。
  需求清单的 A/B 两条路里选了 B（先做数据层），
  但如果朋友要在网页上点着看，还得做 A。
- **调用接口** —— 现在是「读 jsonl」。
  需求清单里写的「curl / Python 库 / MCP 工具」都还没做，
  等有了实际调用方再定形态（免得做出来没人用）。
### 怎么实现（两条路，倾向 B）

**A. 在现有站点上加一个「学习卡」面板**
- 改动小：payload 已经有 `text` / `vision` / `hard` / `altpos`
- 缺点：**payload 已经在 2.6 MB 预算边缘**，再加内容层会爆；
  而且它服务的是「网页浏览」，不是「批量召回」。

**B. 另建一个内容层 API / 命令行（推荐）**
- 输入一个概念名或 id → 输出结构化的「学习卡」JSON
- 内容从**数据层现算**（`data/*.jsonl`），不进 payload
- 站点页面可以调它，也可以是 `curl` / Python 库 / MCP 工具
- 好处：① 不动页面体积预算 ② 离线可用（agent 直接读文件）
  ③ 能给「批量生成学习卡」留口子

**产出物**（无论 A/B 都要有）：
- `data/learn-cards.jsonl` —— 每个概念一条，五面齐全
- `docs/agent-data.md` 补一节 —— 怎么取、字段什么意思、来源标记怎么读
- 一个校验脚本 —— 把上表那几项判据变成可跑的检查

## R-3　数据库层：让项目能被「查」（Milvus）

> **提的人**：2026-10-25，朋友是 **Milvus 生态负责人**。
> 他要用这个项目来自学术理化 —— 但项目现在是个**静态站点 + JSONL**，
> 想「用我自己的话说这个概念」「按学科筛着看」都得自己写脚本。

### 要解决什么

R-1 把「按知识点召回内容」做成了**数据层**（`data/learn-cards.jsonl`）。
但那是给 agent 读文件用的。朋友要的是**一个能交互查询的数据库**：

| 他会问的 | 现在 | 有了数据库 |
|---|---|---|
| 「浮力」在教材里怎么讲的？ | grep JSONL | 一次向量检索 |
| 用我自己的话问「为什么苹果会掉下来」 | 做不到 | 语义检索命中相关段落 |
| 只看人教版八下的 | 自己写过滤 | `filter` 参数 |
| 这个概念的前置是什么 | 看站点面板 | SQL 查 `kg_prereq` |

**核心痛点是召回，不是存储**：
上游概念名大量是改写过的（「ATP（能量储存形式）」「DNA（遗传信息载体）」），
教材里根本不这么写 —— **精确字面匹配只覆盖 4.6%**。
向量检索补的就是这一段。

### 怎么选技术栈（2026-10-25 实测，不是拍脑袋）

朋友推荐 Milvus 之后，**没有直接上**，先按
`milvus-workshop/agent/specs/15-retrieval-tier-selection.md` 的
「检索复杂度阶梯」评估 ourselves。那份 spec 自己的结论是：

> T0 → T1 这一步带来**全部**质量增益；T2（向量）相对 T1 的质量增量是 **0**。
> 而且它是**教学选择，不是工程默认**。

我们自己的实测（12 个「BM25 找不到定义句」的真实概念）：

| 方案 | 效果 | 代价 |
|---|---|---|
| T0 纯 BM25 | 命中 5/5（top-10 里有该概念自己的引文） | 零，13,489 条引文 8 秒建完倒排 |
| T0 + 规则改写 | 2/12 → 7/40（18%） | 零，但规则太粗 |
| 纯语义（`nomic-embed-text`） | **0/15** —— 这模型是英文的，「邻补角」召回「近似数」 | 0.1 秒/条 |
| 纯语义（`qwen3-embedding:8b`） | **4/4 正确项排第一** | 10 秒/条 → 全量 37 小时 |
| 纯语义（`qwen3-embedding` + MRL 512 维） | 质量**完全不掉**（与 4096 维一致） | 2.4 秒/条 |

**结论**：语义检索**确实**是那 4.6% 缺口的解药（qwen3 中文质量实测 4/4），
但**纯向量不是最优解** —— 正确做法是 Milvus 的**混合检索**：
BM25 粗筛 + 向量重排。这也让成本从 37 小时降到可接受。

**本机没有云 API 依赖**：`qwen3-embedding:8b` 和 `bge-m3` 都在本机 Ollama 里
（实测 `ollama list` 有 `qwen3-embedding:8b` 4.7GB / `nomic-embed-text` 274MB），
不外传教材内容 —— 教材有版权，不出境。

### 灌什么

| 表 | 粒度 | 条数 | 用途 |
|---|---|---|---|
| `kg_textbook` | 教材原文**段落** | 57,904 | 主表：向量检索 + 按书/学科/页码过滤 |
| `kg_concept` | 知识点 | 8,590 | 概念定义 + 元信息 |
| `kg_prereq` | 先修边 | 17,164 | 图关系（谁是谁的前置） |

⚠️ **为什么是段落不是整页**：整页 550 字，检索精度差得多。
段落边界按**句末标点**切，不跨句硬断（切在词中间会产生假召回）。

⚠️ **版权页不能进库**：教材前十几页是版权页 / 编者信息
（「版权所有…未经许可不得另做他用」「美术编辑：…」）。
这些页进向量库 = 检索时召回版权声明，
而且**把教材版权信息复制进了数据库** ——
项目一直守着「教材 PDF 不入库、只存抽出来的结构化事实」这条线，不能在这儿破。
所以入库前按关键词 + 汉字密度筛掉（实测 21,948 页 → 57,904 段，版权页 0 条）。

### 关键约束

1. **这一层是「给他查的」，不改变站点的静态性** ——
   站点仍然是一个 HTML 文件，不加载外部资源。
   Milvus 是**本地/自建**的，不进 payload。
2. **入库的是抽出来的段落，不是教材原件** —— 同 `concept-text.jsonl` 的性质。
3. **来源标记必须带进表里**（`edition` / `book` / `subject` / `page` / `chapter`）——
   不然查到一段话也不知道出自哪本书。
4. **不替用户下结论**（跟 R-1 同一纪律）——
   向量检索给的是「相关段落」，不是「这就是定义」。
5. **过滤判据要宁可漏，不要误杀** —— 这一条是量出来的，
   三次判据调整的实测代价见下。

### 过滤判据的实测代价（2026-10-25）

三个判据都试过，**误杀率比想象中高得多**：

| 判据 | 后果 | 结论 |
|---|---|---|
| 页级判「这页有 OCR 残骸」 | 整页丢掉 **7,516 页（35%）**，被误杀的是「分体式位移传感器」「空间向量分解」这种正文 | **不用**：残骸在段落级判，页级只留版权判断 |
| 「拉丁字母占比 ≥12%」 | 误杀 **42%**（57,904 → 33,819）—— 教材里公式和坐标多（`A(4,0),B(6,7)`） | **不用** |
| 「拉丁串紧跟中文 ≥4 次」 | 误杀 **1,110 条好段落**（「同型血可输…」「酸碱度(PH)…」—— 正常缩写就命中） | **不用** |
| 「单字符连续重复 ≥8」 | 0 误杀 | **用** |
| 「≥8 连同一拉丁字母」 | 基本 0 误杀 | **用** |

最终只留两条，保留 **55,242 / 57,904 段（95%）**。

⚠️ **表格不按汉字密度筛**：
「分析下面的资料。类群我国已知种数…哺乳动物581434013.39」这种密度天然低，
但**对自学有用**（有数据才能看趋势）。
密度当判据会误伤 1,132 段。

### 怎么验算做对了

| 检查项 | 判据 |
|---|---|
| 召回有效性 | 「浮力」能召回「…这个力叫做浮力(buoyancyforce)」那段 |
| 过滤可用 | `--edition 人教版 --book 8b` 只返回人教八下的段落 |
| 版权不外泄 | 库里没有含「版权所有 / 美术编辑 / 印刷产品」的段 |
| 覆盖 | 57,904 段覆盖 21,948 页里可检索的正文 |
| 与学习卡不打架 | 同一概念的向量命中段落 ⊆ 学习卡 `read` 面的页 |

### 形态：为什么它是「可选」而不是主线（2026-10-25 定的）

这一层做完之后，回头问了一个问题：**这个形态适合放进开源项目吗？**

**结论：不适合放主线，但值得留在仓库里 —— 降级成「可选实验」。**

三条理由，都是量出来的：

| | 现状 | 这一层 | 冲突 |
|---|---|---|---|
| 交付方式 | 数据层全部入库，agent 直接读文件 | 375 MB 二进制库**不能入库** | clone 下来「少一块」，要自己跑 45 分钟补齐 |
| 依赖门槛 | 零 npm 依赖 + 纯标准库 | +pymilvus +milvus-lite +Ollama +1.2 GB 模型 | 门槛断层 |
| 首次可用 | 立即 | 45 分钟 + 1.5 GB 下载 | 体验断裂 |

**但它的独有价值是真的**，而且只有它能做：

| 需求 | 学习卡（jsonl） | Milvus |
|---|---|---|
| 按概念名查教材原文 | 32% 覆盖 | 全覆盖 |
| 按书/页码查 | **100%，够用** | 一样 |
| **用自己的话问** | **做不到** | **能做到** |

所以定位是：**主项目一行都不受影响，想用的人按 `optional/milvus/requirements.txt` 自己装。**

**为什么不另开仓库**：这层的数据完全来自主仓库的 `lessons.jsonl`，
拆开就要做同步机制 —— 两边的数据层会漂移。

**更正一个先前的担心**：本来以为 `milvus-lite` 会被废弃（所以才锁了 2.5.1），
查了官方仓库 —— **没有废弃**（2026-10-20 仍在提交，464 star），
而且新版定位就是「local development, notebooks, tests, and small-scale AI applications」，
跟我们的用法完全对得上。
**版本锁也解开了**：新版 `milvus-lite==3.2.2` + `pymilvus==3.0.2` 在 Python 3.12 上跑通
（之前锁 2.5.1 是因为本机默认 Python 3.9 装不了新版）。

⚠️ **两代格式不兼容**：3.x 的 `.db` 是目录，2.5.x 的是单文件，**互相读不了** ——
换版本 = 重建（45 分钟）。文档里写清楚了。

### 状态

- `optional/milvus/build_milvus.py` —— 建表 + 灌数据
- `optional/milvus/query_milvus.py` —— 查询（语义检索 / 按名查 / 查前置）
- `optional/milvus/check_milvus.py` —— 校验（8 组判据，含正负例 golden set）
- `data/milvus/milvus-standalone.yaml` —— 官方 compose（Milvus v3.0.3）

**后端两种**：

| 后端 | 怎么用 | 什么时候用 |
|---|---|---|
| **milvus-lite** | `python3 optional/milvus/build_milvus.py` | 单机自用（**当前主路径**） |
| Milvus Standalone | `MILVUS_BACKEND=server python3 optional/milvus/build_milvus.py` | 要多人同时查、要给朋友远程访问 |

⚠️ **milvus-lite 的版本必须配 `pymilvus==2.5.1`** ——
配 3.0.2 起不来（socket 连不上，报 `FAILED_PRECONDITION: … .sock: connect failed`）。

⚠️ **本机实测：Docker 拉不动 Milvus 镜像** ——
`milvusdb/milvus:v3.0.3` + `minio` + `etcd` 三个镜像从 Docker Hub 拉了 **50 分钟一个都没到**，
换 `docker.m.daocloud.io` 源也慢（改 daemon.json 的 registry-mirrors 后
**Docker daemon 直接起不来**，已回滚配置并确认 Docker 恢复正常）。

所以**这台机器上 Standalone 不可用，lite 是可行路径** ——
功能等价（向量检索 + 标量过滤 + ARRAY 字段），代价是不能多人同时写同一个库。
要给朋友远程访问，要么他本地跑 lite，要么找个能拉镜像的机器跑 Standalone。


### 踩过的坑（都在 `optional/milvus/build_milvus.py` 的注释里）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `No index found in field [vector]` | 建集合时没带 `index_params` | 建集合时就把索引一起建 |
| `cannot create index on non-existed field: vector` | schema 里漏了 `vector` 字段 | 检查字段列表 |
| `Failed to parse schema info` / `internal error` | **milvus-lite 不支持 `default_value`** | 缺值在数据层补（`_fill_missing`） |
| `Insert missed an field 'x'` | 记录缺字段 | 数据层补齐 |
| `Attempt to insert an unexpected field 'x'` | 记录多字段 | 同上 |
| `should create connection first` | 用了老的 `Collection()` ORM | 只用 `MilvusClient` |
| `field should be a varchar, but got a int` | `grade` 在图谱里有的是 int、有的是 str | 统一转型（`_to_int`） |
| `evidence` 切片 TypeError | 上游有 40 条 evidence 是 **dict** | 统一转文本（`_to_text`） |
| `Post "http://127.0.0.1:xxxx/tokenize": EOF` | Ollama 在切模型 / 负载高 | 嵌入加重试 + 拆批重试 |
