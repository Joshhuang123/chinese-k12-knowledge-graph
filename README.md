# 中文知识图谱

**中国孩子在学什么？按人教版教材的顺序，一根锥形。**

把 K1 到 K12 的知识点摊开：横向一个知识点就是一个可以单独教、单独考的小概念，纵向是年级。每个点之间的连线是「先修」——学上面这个之前，得先会下面那个。

单文件、零依赖、不联网。

**在线玩**：https://joshhuang123.github.io/chinese-k12-knowledge-graph/ （GitHub Pages）

**上海版**：https://joshhuang123.github.io/chinese-k12-knowledge-graph/shanghai.html
（上海的孩子按**沪教版/沪科版**教材的顺序看，同一套前置关系 + 教材原页上的公式和难点）

**本地玩**：双击 `index.html` 或 `viz/知识图谱3D.html`（上海版是 `shanghai.html`）
—— **不需要装任何东西**（零 npm 依赖，数据层是 jsonl，agent 直接读）。

> 有一个**可选**的向量检索层（用自己的话问教材），见「九之四」。
> 它需要额外装依赖和模型，**不装不影响上面任何功能**。

## 这个项目是什么，不是什么

**不是**「再做一个知识图谱」。北大那套 K12-KGraph 做得比我们好，我们不重做，也不重标数据库。

**是**在它上面补一层两件事：把异构的原始数据归一化，然后**校验**。

因为上游自己漏了两个环：

- 「极性分子」说学「相似相溶规律」前要先会它，反过来也这么说 —— 逻辑上不可能同时成立
- 「化学键能量变化与反应热」和「根据键能估算反应热」互为前置

这些边都在官方 `global_KG/edges.json` 里，不是我们归一化造出来的。K12-KGraph 的论文 §10.2 明确写了 `is_a` 和 `prerequisites_for` 两个子图都做过 DAG 检查并「yielding valid DAGs」，但实际有 3 个环（`prerequisites_for` 两个二元环、`is_a` 一个三元环）。

**已向上游上报**：[#8 环](https://github.com/haolpku/K12-KGraph/issues/8)、[#9 空名节点](https://github.com/haolpku/K12-KGraph/issues/9)。

**校验本身也需要被校验** —— 这是这个项目真正的立足点。详见 [`known-issues.md`](known-issues.md)，包括我们自己的校验层出过的 bug。

## 这个项目有什么数据

**35 个数据集，142 MB，7 种以上字段结构。**
不知道用哪个的话，读一个文件就够：

```bash
cat data/DATASETS.json      # 机器可读（含每个数据集的字段表和样本行）
```

或者**直接在浏览器里看**：**[`data.html`](data.html)**（静态单文件，能搜），
或者看人读的表格：[`docs/data-catalog.md`](docs/data-catalog.md)（自动生成，跟数据同步）。

按需求查：

| 你想干什么 | 用哪个 |
|---|---|
| 「某节课讲了什么」 | `data/lessons.jsonl`（人教）/ `lessons-sh.jsonl`（沪教） |
| 「这个概念的教材原话」 | `data/concept-text.jsonl`（人教）/ `concept-text-sh.jsonl`（沪教） |
| 「公式和图形」 | `data/concept-vision*.jsonl` |
| **「我要自学这个概念」** | **`data/learn-cards.jsonl`** —— 六个面一次给全，每段带来源标记 |
| 「这个概念在教材哪几页」 | `data/page-index.json` |
| 「这个概念前面该学什么」 | `learn-cards.jsonl` 的 `prereq` 面（跟站点「学习路径」面板同源） |
| 「用自己的话问教材」 | Milvus 层（**可选**，见九之四） |

字段说明和取用示例在 [`docs/agent-data.md`](docs/agent-data.md)。

### 二、脉络视图：两个没人发现的 bug

「脉络」视图想回答「这个点是从哪条路长出来的」。原来的实现有两条错：

- **56.9% 的线在图谱里根本不存在** —— 所有节点被直连到根，
  2,253 条线里 1,281 条是编的
- **直接前置被推到更远的列** —— 取的是「最长层数」，不是「最短距离」

改成记 `parent`、画 parent→child、BFS 首次发现即最短距离后：**假线 0 条，被推远 0 个**。

### 三、「卡在哪」：把图谱变成能回答问题的工具

原问题一直是一个：**「朋友最近在二次函数上卡住，是因为什么前置的缺失」**。

诊断层只能指「哪一环最可能是空的」——不能确诊，也不能说「先修这个」，
因为**教材顺序 ≠ 先修**。但按**杠杆 × 早晚 × 是否链根 × 离症状距离 × 覆盖薄弱**
排完序之后，每一条都附一句人话理由，还能一键复制成选题卡。

### 四、教材：两条通道

这是本轮最大的一块。

**先说清楚为什么不能抽全文。** 教材是扫描件，而且数学页的 PDF 文本层本身就是坏的——
公式字体的 ToUnicode 表缺失，取出来是 `!"#$%&'"()*`。
OCR 救回了汉字，但 `S=ah` 变成「S一ah」，图形整个丢了。

于是走了两条通道：

| | 产物 | 拿到什么 |
|---|---|---|
| **OCR 层** | `data/lessons.jsonl`（12,939 页）<br>`data/concept-text.jsonl`（1361 个概念） | 教材**说了什么**：正文原话、章节、页码。291 个概念拿到**教材自己的定义句** |
| **视觉层** | 人教 `data/vision-pages.jsonl`（4,390 页）<br>其他版本 `data/vision-pages-alt.jsonl`（7,784 页）<br>上海 `data/vision-pages-sh.jsonl`（3,789 页）<br>→ `data/concept-vision.jsonl`（2,012 个概念）<br>→ `data/concept-vision-sh.jsonl`（569 个概念） | 教材**画了什么 / 写了什么式子**：人教 20,801 条 LaTeX 公式、7,165 个图形语义、11,712 道例题；上海 24,523 条公式、4,544 个图形语义、9,227 道例题 |

视觉层是让多模态模型**直接看渲染出来的页面**。这不是「把 PDF 抽成文本」，
是**换了一条信息通道**——OCR 读的是**编码**，视觉读的是**版面**。
同一页（人教九上 p45，顶点式）：

```
OCR  →  狔＝狓２ 之类残骸
视觉 →  y = \frac{1}{2}(x-6)^2 + 3 · 顶点 (6, 3) · 对称轴 x = 6 · x=3..9 的取值表
```

几何页同样管用：八下 p30 的图 17.1-6（赵爽弦图）——四个全等直角三角形（红）
+ 正方形（黄）、三步割补、旋转平移弧线箭头、a²+b²=c²，
连练习第 2 题的**勾股树**都认出来了。

**一条铁律**：公式和例题题干是页面原文，可以直接引用；**图形描述是模型转述**，
引用必须标「据图」。每条都带 `provenance` 字段，体检里有一条断言专门盯它。

### 五、教材自己标的难点：面板里第一次有了**一手**的依据

「卡在哪」面板原来的排序信号（杠杆 × 早晚 × 覆盖薄弱）**全是模型推断的**。
而教材里一直躺着一份一手的东西没用过：

> **「思考」框和「探究」框** —— 教材编委会自己标的难点。

人教 31 册实测 1,359 处，归到 **291 个概念**上、522 处指名。
**教材说这里难** —— 这比任何推断都硬。面板里现在直接写：

```
教材在这里标了 6 处思考/探究 · 八下 第一节 函数
例：从前面的例子看，你认为三种表示函数的方法各有什么优点？
```

按概念排：反比例函数 10 · 立体图形 8 · 血液 8 · **二次函数 7** ·
圆心 7 · 视图 7 · 同位角 6 · 温度 6 · **函数 6** · 一元二次方程 6。

再叠一层**教材的跨节引用**（一节的公式里出现更早的节的概念的公式），
跟「教材难度 × 图谱覆盖」交叉，得到一张**内容缺口地图**：

| 册 | 节 | 教材标难点 | 概念 | 图谱前置覆盖 | 0前置 |
|---|---|---|---|---|---|
| 八上 | 第一章 动物的主要类群 | 39 | 53 | 0.1 | 50 |
| 七下 | 第一节 相交线 | 32 | 7 | **0.0** | 7 |
| 八下 | 第二节 一次函数 | 28 | 11 | 0.3 | 9 |

**教材标了 32 个思考题、而图谱里这 7 个概念一个前置都没有** —— 七下「相交线」
（邻补角、对顶角、同位角、内错角）就是这样。**教材认为这是难点，
我们的数据在这里是空的。**

账本在 [`docs/textbook-difficulty.md`](docs/textbook-difficulty.md)。

### 八之二、人教版《小学科学》：把图谱最空的那一段填上

**上游 issue #10 的另一半，做完了。**

上游 K12-KGraph 的图谱里，**小学阶段只有数学**（1,182 个概念）——
物理、化学、生物学在小学一个都没有（那就是 issue #10 提的事）。
但**教材是有的**：国家中小学智慧教育平台上，人教版《小学科学》
1 上~6 下 **12 本 / 1,036 页**全套在。

所以这一层做的事是：

> **教材上的概念 → 挂到上游那个概念上，同时标出它在小学科学哪本书哪一节哪一页。**

**不造节点**（图谱结构不变，先修边还是上游那套），
只是给已有节点补一条「它在小学科学三年级上册第 2 页『磁铁的磁极』」。

那些概念**在上游图谱里都存在**（磁极、热胀冷缩、电磁铁、光合作用……），
只是上游把它们标在初中/高中册次 —— 小学科学三上就在教了。
这个做法跟上海站「小学科学的内容拆进物理/化学/生物」是同一思路。

| 环节 | 做法 | 产出 |
|---|---|---|
| 抓教材 | 平台索引 3,565 本 → 筛小学科学 115 本 → 按出版社去重取人教版 12 本 | 1,036 页，1303×1842，0 坏文件 |
| 视觉层 | 页图 → 视觉问答（公式/图/表/例题） | 1,030 页成功 / 6 页失败（空白页） |
| 目录 | **视觉模型读目录页**（12 本 / 57 单元 / 233 节） | `data/kx-toc.json` |
| 原文 | tesseract chi_sim --psm 6 | `data/kx-ocr.jsonl`（1,036 页） |
| 匹配 | 四信号（目录 / 目录近似 / 集中 / 同册）+ 同名消歧 | **146 个概念**定位到小学科学的书/节/页 |

**三处踩过的坑，都写进代码注释了：**

1. **平台元数据说的出版社是错的。** `provider_list` 写「人民教育出版社」，
   但封面印刷体印的是「**湖北教育出版社**」—— 人教社编写、湖北版出版。
   12 本封面都用视觉模型逐本读过，两个都要记。
2. **目录的页码是印刷页码，页图文件是扫描序号。** 差 5 页（3a）或 3 页（4b/5b/6b）。
   不换算就整本错位 —— 目录说「食物的营养 /58」，
   实际那本从扫描第 63 页才开始。**偏移量由 `detect_offset()` 从页脚数字实测得出，不写死。**
3. **节名 ≠ 概念名，而且「单元回顾」不算一节课。**
   「磁铁的磁极」⊃「磁极」、「植物的光合作用」⊃「光合作用」——
   标题要**包含**匹配（3 字以上任意包含，2 字只认后缀）。
   而「单元回顾」复习整个单元，「导体/电流/绝缘体」在那儿出现
   不代表「这一节讲它」，要排除。

**接进页面**：`data/concept-vision-kx.jsonl` → payload 的 `kx` 字段 →
「卡在哪」「学习路径」面板里显示成青色的
`小学科学 · 《科学》三上 · 家庭用电 › 手电筒的秘密 · 第 36 页`。
用青色边跟别的教材信息区分 —— 它是**另一套教材**，
别让人以为那就是人教版初中物理那本。

| 抓教材 | 平台索引 3,565 本 → 筛小学科学 115 本 → 按出版社去重取人教版 12 本 | 1,036 页，0 坏文件 |
| 视觉层 | 页图 → 视觉问答（公式/图/例题） | 1,030 页成功 |
| 目录 | **视觉模型读目录页** | 57 单元 / 233 节 |
| 节判定 | **视觉模型读每一节的正文首节页** | 105 节 → **68 个概念 / 37 个活动** |
| 原文 | tesseract chi_sim --psm 6 | 1,036 页 |
| 建图 | 目录 + 判定结果 → 节点 + 教材序边 | `data/kx-graph.json`（67 节点 / 25 边） |

**为什么要读正文，不能只看节名**：节名筛不出概念 ——
「磁铁的磁极」是概念，「不倒翁」是对象，「蚕出生了」是过程，
「建造微型植物工厂」是项目。**读了正文才知道这一节实际在讲什么。**
视觉模型给的判定：105 节里 68 个是可教的知识概念，37 个是活动/回顾/制作。

**67 个节点分两类**：
- **56 个小学特有** —— 上游图谱里完全没有这些概念
- **11 个对齐上游** —— 同一个知识点在两套教材里都有
  （5 个同名：溶解/空气/光的色散/视觉的形成/电动机；
  6 个人工确认：感觉器官/热胀冷缩/生物与非生物的区分/能量的转化…）
  页面上的位置写成「一上·家养动物 › 更多的家养动物（**上游：七上**）」——
  **上游册次放括号里当注脚**，因为「上游标在七上、小学一上就在教」正是这一站最该让人看见的事。

**边只有两种，来源码分开标**：

| 来源码 | 含义 | 页面上 |
|---|---|---|
| 0 上游 | 上游图谱的先修关系（照搬） | 实线 |
| **8 教材序** | **教材编者排的教学先后** | **虚线 + 紫灰虚框徽标** |

**「教材序」不等于「先修关系」** —— 这是这个项目自己的结论
（12s 那期视频的 s5 专门讲了这事：教材里大量回顾旧例引新课，那是衔接不是前置）。
所以这一站的边**绝大部分是教材序**（24 条教材序 + 1 条上游先修），
页面上明写「虚线是教材序，不是先修关系」，徽标也用虚线边框跟其余七档区分。

**教材序边按单元内连**，不按整册 —— 单元之间是并列的（并列的单元不该有先后边）。

**教材原话 19 个概念**（宁缺毋滥）：小学科学的教材给汉字注了拼音，
OCR 会把拼音一起读出来（「tai yang shsng」）。
所以要剔拼音、剔页眉页脚、**取最长的连续汉字串**，
而且**原话必须提到这个概念名**（否则会选到同页别处的句子）。

**没做到的**：这一层**没有补「小学科学自己的概念」的先修关系** ——
新概念之间的边只有教材序（编者排的顺序），不是真正的先修关系。
要补就得自己推，那跟上游那套「模型重建的先修边」是同一个性质的东西，
得另立来源码，不能混在一起。

### 九、上海版独立站点：上海的孩子按沪教版在学什么

https://joshhuang123.github.io/chinese-k12-knowledge-graph/shanghai.html

**3,503 节点（3,453 个沪教概念 + 50 个前置补充）· 5,552 条先修边 · 1,350 个教材单元 · 354 章。**
复用主站同一个 `viz/template.html`，**只换 payload** —— 模板不知道数据是人教还是沪教。

### 沪教概念是怎么来的：上游 8,590 个人教版概念 ∩ 沪教版教材

上游图谱**只按人教版拆过概念**（人教版 873 个教学单元 → 8,590 个概念，
每单元 9.8 个）。沪教版教材有 **1,276 节** —— 按同样颗粒度拆应该是
**~12,500 个概念，比人教版还多**。

所以沪教站的 3,453 个概念 = 上游那 8,590 个里「能在沪教版教材上定位到」的子集，
**不是沪教版教材的知识点全集**。两道工序决定这个数：

**① 匹配（`src/vision_to_concepts_sh.py`）** —— 每个上游概念去沪教版教材上找位置。
证据分四档，从强到弱：

| 证据 | 含义 | 数量 |
|---|---|---|
| 目录 | 教材用这个名字开了一节 | 479 |
| 集中 | 教材里成片出现，且这里讲得最多 | 516 |
| **正文** | **概念名出现在教材正文里** | **1,340** |
| 同册 | 同一册 + 某个图注/题干里出现过 | （只作辅助，不单独成立） |

**「正文」这一档是 2026-10-26 加的**（ISSUE-49）。
原来命中计数只用 `topical_blob` —— **只取图注/表题/题干，不含教材正文**。
那个设计对「引用教材的公式和图」是对的（要干净、不能带模型转述），
但拿来当**概念匹配**输入就太窄：教材的知识点恰恰写在正文里。

实测（`src/probe_edition_gap.py` 四象限）：

| | 修前 | 修后 |
|---|---|---|
| 正常进来（沪教教材有，且匹配上了） | 2,258 | **3,356** |
| 漏匹配（沪教教材有，却没进来） | **1,123** | **25** |
| 误匹配（沪教版其实没有） | 115 | **97** |

**② 教材边界闸**（`src/shanghai_taught.py` + `src/shanghai_relocate_rjb.py`）——
先修闭包会一路拉回上游人教版图谱，混进人教版节点（实测 975 个，28.8%，
549 个是高中概念：ATP、DNA 双螺旋、σ键、sp²杂化轨道…）。
留着的话搜「ATP」会同时出「ATP（腺苷三磷酸）沪科版·必修一」和
「ATP水解供能 人教版·必修一」—— 同一知识点被拆成两个节点。
所以按**「沪教教材教不教」**过一道闸，再按**「沪教教材真把它当知识点教吗」**
过第二道（跟沪教节点集同一套「目录/集中」判据）。
**站里现在一个人教版节点都没有。**

**五个学科都在**：数学 26 本 · 物理 14 本 · 化学 9 本 · 生物 9 本 · 小学科学 9 本，
沪教版（上海教育出版社，五四学制）和沪科版（上海科学技术出版社，六三制）两套并行。

卡片上现在有四样教材证据：**教材原话**（教材自己写的定义句，2,131 个概念里有 617 个有）·
**教材位置**（哪本书哪一节第几页）· **教材原书上的公式**· **教材自己标的难点**。
还有一个**「学习路径」**面板：把这个知识点之前要会的东西，按先修关系排成一条路，
每一步标出它在教材里的位置 —— 补课、排课照着翻书就行。

上海版的**数据质量页**在 <https://joshhuang123.github.io/chinese-k12-knowledge-graph/shanghai-quality.html>，
里面有上海教材这一层的账和**内容缺口地图**（教材标了难点、而图谱前置薄的地方）。

难的不是画图，是**认得出哪些概念是这本教材教的**：

- **人教和沪教不能混在一个册次桶里。** 沪教版七上从「第 10 章 整式的加减」起，
  人教版七上从「第 1 章 有理数」起 —— **同一册两版内容对不上**，
  按「同册」筛概念，沪教版七上教的「因式分解」「分式」「轴对称」一个都认不出来。
- **光靠「页面里出现过」也不行。** 「小数」「分子」「等式」在 20 本书的题干里都出现过，
  它们不是「这本书教这个概念」的证据。
- 所以改成四个信号：**目录**（教材自己写的目录，最硬的证据）·
  **目录近似** · **集中**（在这本书成片出现，且占它在全部 26 本沪教书里命中数的 1/3 以上）·
  **同册**。941 个书-概念对里，**没有一条是「页面里出现过」单独成立的**。

**学段必须逐节点算**：沪教版是五四学制（**六年级已经是初中**），
沪科版是六三制 —— 同一个年级号在两套学制里学段不一样。

**先修边接上了自建层**：上游图谱里「二次函数」一条前置都没有，
它的前置全是本项目自建层补的；不接这层，「二次函数卡在哪」根本没法回答。

顺带查清一件事：**平台上的沪教版数学就是 20 本。**
缺的三下/四下/五下/八下/九下是**青岛出版社**和**山东教育出版社**的同名书，
混进上海站就是造假。详见 ISSUE-40。

### 九点五、视觉：学 Marble 的海报感，但保留我们的语义

2026-10-28 用户看了 Marble（withmarble.com/curriculum）的可视化，
说「比咱们的好看」。逐条对比后改了四处：

| | 原来 | 现在 |
|---|---|---|
| **标题** | 60px 无衬线粗体 | **80px 中文衬线**（Songti SC / 思源宋体 / Noto Serif CJK），粉色「学什么。」 |
| **左栏** | 说明文字**互相叠在一起**（#attr 定位 bug） | 全部可读：衬线标题 → 说明 → 计数 → 搜索 → 导航 → 署名，一条线下来 |
| **浮层** | 图例是纯文字行；工具栏按下态是**纯白底** | 左右各一块**玻璃面板**（圆角 + 描边 + 背景模糊 + 阴影）；按下态改品牌粉低饱和 |
| **点** | 纯色圆点 | 大点加一层低透明度**光晕**（不用 shadowBlur，手机端扛不住） |

**借的是表现层，不是内容。** Marble 的图是一团没有结构的「毛球」；
我们的**锥形 = 教材年级分层**，这是他们没有的语义，没动。

标题为什么敢用衬线：模板原来写的是 `'DM Serif Display', Georgia, serif` ——
那个字体**根本没有中文字形**，中文一直在往 generic serif（宋体）**悄悄**回落，
还跟西文 Didone 混排。现在是**显式声明**的中文衬线，标题全中文，不存在混排。
`src/test_search_browser.mjs` 第 [1d] 组判据随之改写：
从「必须无衬线」改成「**必须显式声明** + 渲染结果必须等于声明的那款字 +
声明栈第一项不能是西文字体」—— 守住的是**意图**，不是当年的解法。

**层间距也改成自适应的**（ISSUE-47 的续）。原来 `LAYER_MIN_GAP` 是一个
写死的 26px，三个站共用 —— 但三个站的**层半径差很多**，同样的间距在不同站里
读出来的形状不一样：上海站的锥形窄一半，看着像喷泉而不是分层。
现在按**该站自己的平均层半径**算：主站 26（不变）· 上海站 16 · 小学站 8。

改完**密度判据反而更宽松**（不是更严）：
每点占画布面积 上海站 33.5 → **28.3**（上限 40）· 跨站比 1.87 → **1.58**（上限 2.0）· 主站 17.9 不变。
也就是说上海站原来那个「看着稀疏」的问题，一半是间距写死造成的。

### 十、学习页站点：一个知识点一页

https://joshhuang123.github.io/chinese-k12-knowledge-graph/learn.html

图谱站回答「这个知识点在哪本书哪一节、缺哪些前置」。
**学习页**回答的是下一个问题：**「我到底会不会，卡在哪」**。

一个知识点一页，六个板块：

| 板块 | 内容 | 从哪来 |
|---|---|---|
| **讲解视频** | 外部视频（B站/YouTube/直链），按知识点挂载 | `data/learn-videos.json`（**运行时读，改完不用重建**） |
| **教材原页** | 该概念在教材上的**那一页原图** | 沪教版：国家中小学智慧教育平台的页图直链（67 本沪教教材）<br>人教版：**从本地教材 PDF 渲染**的页图（31 册 / 1,128 页，入库） |
| **教材原话** | 教材自己写的定义句 / 提及句，带页码 | `data/concept-text-sh.jsonl`（沪教）/ `concept-text.jsonl`（人教） |
| **公式 / 图** | 教材原书上的公式和图（**转成纯文本**，不引 KaTeX） | 概念视觉层 |
| **练一练** | 可自动判分的选择题，答完给解析 | `data/learn-questions.jsonl` |
| **前置 / 后继** | 往前追，看卡在哪一环 | 站点 payload 的先修边 |

**三版共用一个引擎**：`?v=sh`（沪教版/沪科版）· `?v=rjb`（人教版初中高中）· `?v=kx`（小学科学）。
数据分三个文件按需加载，`file://` 下也能双击打开（用 `<script>` 而不是 `fetch` ——
后者在 `file://` 下被 CORS 挡掉）。

**能进得来，也能翻得动。**

- **入口**：三个站首页都链到学习页，学习页顶部能链回主站。
  （学习页原来是个**孤儿页** —— 站里没有一处链得过来，也没有一处链得回去。）
- **按教材翻**：首页按**册次 → 章节 → 知识点**三层展开，按小学/初中/高中分组。
  「能力底座 / 自建概念 / 教材缺口」这类**不是某一册教材**的东西另起一区，
  不混在教材册次里让人误会。
  （原来只有「按年级进」，点进去是几百个概念的平铺列表 —— 对学生等于没有导航。）

**学习页也海报化了（2026-10-28）**。

学习页是**另一套模板**，上一轮视觉升级只改了三个图谱站 —— 学习页完全没吃到，
同一个站里于是有了两个视觉系统。现在补上：

| | 原来 | 现在 |
|---|---|---|
| **首屏** | 一堆 `.card` 堆在一起，没有主视觉 | **hero 区块**：kicker（版本名 + 琥珀点）→ 中文衬线大标题「一个知识点，**一页**。」→ 说明 → 统计 chip |
| **节点页标题** | 28px 无衬线 | **中文衬线** 26–40px，知识点名本身就是那张海报 |
| **底纹** | 纯色面板 | 极淡网格 **0.055** + 两团低透明度径向光（暖色 / 品牌粉），跟图谱站画在 canvas 上那层同一套规则 |

三个版本（沪教版 / 人教版 / 小学科学）**共用这套 hero**，一起受益 ——
沪教版就是上海孩子用的那个，所以这轮改动它同样吃到。

判据加在 `src/test_learn_site.mjs` 第 [1b] 组（跟主站那条 [1d] 同一套思路，各测各的）：
① 字体族**显式声明** ② 渲染结果必须等于**声明的那一款**字（像素指纹）
③ 声明栈第一项不能是西文字体。
判别力自检：`.hero h1` 改回 sans-serif → 报红 2 条；全局 `h1` 改回 sans-serif → 节点页那条报红 1 条。

**首屏不等数据**（2026-10-28 线上实测后加的）。

线上实测：学习页要 **45 秒**才出内容。不是渲染慢 —— 是**串行**加载 9 个数据脚本：
`data/learn-sh.js` **4.4 MB**（主数据）先走 35 秒，剩下 8 个（合计 ~350 KB）再串行排 10 秒。
这段时间页面上只有「加载中 / 数据文件…」五个字，等于一片空白。

改法：
- **hero 不依赖数据**（只有那几个统计 chip 依赖）→ 先把海报画出来，数据到了再补数字；
- 主数据与支撑数据**并行**加载（它们互不依赖）；
- 顺带修一个隐患：`data/learn-explains.js` 原来被塞在
  `if (!PAGE_OFFSETS_SH …)` 条件块里 —— 页码偏移量若已加载，讲解稿就永远加载不上。

判据在 `src/test_learn_site.mjs` 第 [1c] 组：用请求拦截把主数据**拖慢 4 秒**，
断言那一刻海报已经在、加载提示在、统计数字**还没出现**（数据没到就不编数字），
数据到了之后统计数字补上、提示撤掉。
判别力自检：撤掉 `renderShell()` → 报红 3 条。

**讲解视频：同一份稿子，两个呈现。**

每个概念一页有**讲解视频**（60 秒左右，横版）和**讲解稿的文字版**。
两者**同源** —— 稿子写一次，页面上不会出现「视频讲一套、文字写另一套」。
**不看视频也能走完**：文字版就在视频下面，一段一段对着读。

视频不是抽象动画，是**讲义视频**：主视觉是**教材原页图**（真东西），
左边是那一页，右边标着它在第几章第几页。

```
data/lesson-scripts/<版本>_<id>.json   ← 唯一的手写输入（讲解稿）
   ↓
prep.js 切句 → tts.js 串行 TTS → rebuild-timeline.js 真值时间轴
   ↓
build-audio.js 拼整轨 → inject.js 注入模板 → shot.js 每句截一帧
   ↓
mux-shots.sh ffmpeg 合成 → video/<版本>_<id>.mp4（+ .jpg 封面帧）
```

**为什么是「每句截一帧」而不是逐帧**：讲义视频是静态幻灯片，
逐帧渲染 60 秒 × 24fps = 1,440 张 PNG，一条要 3–5 分钟，批量根本跑不动。
改成每句一张（字幕烤进画面），一条只要十几秒。

**选片判据**（`src/make_lesson_drafts.py`）：有教材页图 + 有教材原话 + 核心概念 +
**教材自己标过难**（`data/normalized/textbook-hard.json` 里教材的「思考 / 探究」题挂在谁名下）。
最后这条是第一手依据 —— 不是我们觉得它难，是教材觉得它难。

**写稿口径**（`docs/lesson-script-protocol.md`）：总口播 230–300 字 · 钩子 15–30 字 ·
五场固定 · 钩子四型同批不许连着同型 · **数字一律汉字**（公式里的除外）·
**教材原话一字不改**（OCR 残骸宁可整段省略，不引用错话）·
页码用**印刷页码**（书上印的），不是 PDF 扫描序号 · 链用**前置**，没有前置就画「接下来会学」
（画成线性链会谎报先后）。

**稿子也要体检**（`src/check_lesson_scripts.py`）。

讲解稿是这条产线唯一的���写输入，它要是写错了，
视频、页面文字、讲解卡**全都是错的，而且看起来完全正常**。
所以写完必须自己验一遍，判据跟协议一一对应：

| 判据 | 为什么 |
|---|---|
| `definition` 跟素材包的定义有 **≥6 字公共子串** | 定义是「自己写」的，但**不许凭空另编** —— 逐字相同太严（同一句话可以有不同措辞），完全不管太松 |
| `quote.text` 在素材包的 `quotes` 里**逐字存在** | 教材原话一字不改；残骸宁可不写这个字段 |
| `formulas` 每条都在素材包里**逐字存在** | 公式不许改写（实测有人把 `F浮 = ρ液 g V排` 加成 `F浮 = ρ液 · g · V排`） |
| `page.image` / `page.where` 跟素材包一致 | 页图和印刷页码都以素材包为准，稿子不能自己拼路径 |
| `explain.lines` 与 `scenes[].text` **逐字一致** | 页面文字版 = 视频配音版，说错一个字就是两套内容 |
| chain 里每个名字都在素材包的前置/后继里 | 把后继说成前置 = 谎报先后 |
| 总口播 230–300 字 · 钩子 15–30 字 · 数字全汉字 | 协议硬约束 |

跑完是 **43 份稿子 · 1349 项 · 全绿**。

**这套体检当场抓出 6 类真问题**（都不是「看起来不对」，是判据抓得住的）：
1. **9 份稿子字数不足**（213–227 字，差 7–17 字）—— 补到 240–260；
2. **7 份稿子的页图地址过期**（人教版页图从外链改成本地 WebP 之后没跟上）；
3. **2 条链方向倒错**（前置被标成「接着学」）；
4. **1 条公式被改写**（擅自加 `·` 分隔符）；
5. **1 份老稿引用了一句无源教材原话**（「冰山、游船、鸭子……」在任何源数据里都查不到）
   → 按协议**整段删掉**，换成素材包里确实有的图和思考题；
6. **12 份沪教版素材包还指着「页首优先」修复前的旧页**（扫描页 131 vs 现在的 133）
   —— 意味着**视频和学习页指着不同的页**。素材包全部对齐到当前数据。

顺带把素材包生成器补了两处：
- `--only <id>`：**定向**给某个概念建素材包。
  有些核心概念**没有教材原话**（如「浮力」），永远进不了选片，
  于是稿子**没法自检**（没素材包就查不了原话/公式/页码）。
  `--only` 绕过「必须有教材原话」和「教材标过难」两条**偏好**，
  但**保留**「印刷页码算不出来不选」「印刷页 ≤ 0（选到前言页）不选」两条硬规则。
- 素材包的 `formulas` 现在**合并上游教材原式**（`graph.json` 的 `props.formula`）。
  视觉层会漏掉一些式子（浮力的 `F浮 = ρ液 g V排` 就不在视觉层的 `f` 里），
  不补进来的话，写稿的人只能自己排版 —— 那就是改写。

**管线的几个坑**（都写在脚本注释里）：
- **TTS 是串行配额** —— 实测 28 秒/句；**并发 2 路反而更慢**（6 句 358 秒）。
- **改了稿子文字，旧音频不会自动作废** —— 音频文件名是 `<场id>_<句序>`，跟文字无关，
  TTS 认文件名就跳过 → **配音是旧的、画面文字是新的**，而所有检查都显示正常。
  现在逐句比对 `texts.json`，变了就删掉那句 mp3。
- **索引要两个文件一起写** —— 页面读 `data/learn-videos.js`，
  而构建读 `data/learn-videos.json`。只写一个 → 视频做完了页面上也挂不上。
- **改了讲稿的音频要重合成** —— 只改 mp4 不重 mux，画面和音轨会错位。
- **成片必须真的能解码** —— 2026-10-28 撞上：21 条成片里有 1 条 mp4 的
  mdat 是坏的（`Invalid NAL unit size` × 4000+）。文件在、封面帧在、索引正常，
  **所有已有的检查都显示正常** —— 但视频播不出来。
  ⚠️ `ffprobe` 只报时长是**抓不住**的：moov atom 完整，时长读得出来，
  但 mdat 里是垃圾 → 探时长通过、解码失败。
  所以判据必须**整解码一遍**（`ffmpeg -f null -`，一条 0.66 秒），
  已加进 `src/check_learn_site.py`。
  判别力自检：往 mp4 中段注入垃圾 → 报红 1 条；还原 → 绿。
- **索引不能是「累积式」的** —— `write_indexes` 以前只处理**这轮**跑过的稿子，
  其余靠「读磁盘再并进来」保住；而那个合并**只加不减**，
  加上循环里清「早期裸 id 键」的 pop，就出现了
  **条目被删掉后再也补不回来**的情况：
  实测两条视频的 mp4 文件一直在，索引里却没了 → **学习页上挂不出来**。
  现在索引改成**全量重建**（扫所有稿子，凡有成片的都写进去），
  并加判据「每条成片都在索引里」「索引里没有指向不存在文件的条目」。

⚠️ **上游的概念 id 是跨版本共享的**（沪教版 3,503 个 id 在人教版里全都同名，
但指向不同的教材位置）。所以**键和文件名都要带版本前缀**（`rjb:math_9b_rjb_cpt1`、
`video/rjb_math_9b_rjb_cpt1.mp4`）—— 否则人教版的视频会挂到沪教版的概念上。

**页码有两套，页面上写的是「书上印的那个」。**

- **扫描序号**：PDF / 平台扫描本的第几页 —— 用来定位图片
- **印刷页码**：书上印的那个 —— 用来让学生翻书

两者差着封面、版权页、导引、目录的页数（实测 4–7 页）。
写错的代价很具体：沪教版七下数学，面板写「第 16 页」，图上页脚印的是 **9** ——
学生按 16 翻书，翻到的是下一节。

- 人教版：`src/build_page_offsets.py` —— 从**本地 PDF 页脚**取页码（31/31 册）
- 沪教版：`src/build_page_offsets_sh.py` —— 从**平台 OCR 的页脚行**取页码（44/67 册），
  并用「印刷页码必须随扫描页单调递增」这道独立判据兜底

**取不到偏移的册次不猜** —— 页面上老老实实写「电子教材扫描页 N」。

**练习题是自己出的，不是抄来的。**
上游 [cn-math-taxonomy](https://github.com/xiaoyang111222/cn-math-taxonomy) 有 9,399 道题
（CC BY-NC），但它的概念名跟我们的**只重合 12.3%**，自动映射的召回只有 1.1%
（实测见 `src/probe_mapping.py`：对方的「单元/章/节号」三段命名跟我们完全不同，
纯名称模糊匹配会错配成「5以内的加法」→「10以内的加法」）。

所以题从**教材原话和图谱定义**反推，两种题型：

- **定义配对**：「下面哪一句是教材给「X」下的定义？」—— 1 句真定义 + 3 句别的概念的真定义
- **概念配对**：「教材里说『……』——说的是哪个概念？」

关键的一步是**把概念名挖空**（「几个单项式的和叫做＿＿」）：
教材的定义句本来含概念名（「几个单项式的和叫做整式」），
不挖空的话学生不看选项就知道答案 —— 这跟「题干泄露答案」是同一件事。

质量闸卡得很严（宁可少出，不出废题）：
定义句必须**完整收尾**、**括号配对**、**含定义动词且动词在后半段**、
**被挖掉的位置必须紧跟定义动词**（不然「因数」题会拿「最大公因数就是1」当答案）、
挖空后**只能有一个空**。

产出 **397 道**（沪教 212 · 人教 185）。每一道都能回教材对。

**教材原页图：两个来源，页码体系不同源**

| 版本 | 来源 | 为什么 |
|---|---|---|
| 沪教版 / 沪科版（67 本） | 国家中小学智慧教育平台的**官方扫描页图直链** | 平台有完整的沪教扫描本，**外链**，仓库里不存教材内容 |
| 人教版（31 册 / 1,128 页） | **从本地教材 PDF 渲染**的 WebP，**入库** | 平台只有 2024 审定新版（小学）和不同印次（初中），**页码对不上**；本地 PDF 才是我们数据的来源，渲染出来的图**页码天然对齐** |

平台侧的实测结论（`src/verify_page_alignment.py`）：
平台上小学数学只有 **2024 新版**（目录是「认识立体图形」），我们数据是 **2022 旧版**；
初中同一本第一章，平台第 31 页已经是第二章首页，我们第 31 页还是第一章末的习题。
**硬拼会翻到错的页**，所以人教版走本地渲染。

页图用 **WebP**（1055px 宽 44 KB，JPEG 要 91 KB），
1,128 页共 **82.1 MB**。渲染脚本：`src/render_page_images.py`。

### 启发：Marble Skill Taxonomy（美国）

**不是数据来源，也不是代码来源。** 这两件事要分开说，因为很容易被说混：

- **数据没用到。** 本仓库里没有任何 Marble 的数据。 Marble 的 `topics.json` / `dependencies.json` 归 ODbL 1.0，其撰写的文本内容归 CC BY-SA 4.0 —— 这两份许可**都没有出现在本仓库里**。
- **代码没抄。** `viz/template.html` 这套手写 canvas 3D 渲染器是本项目自己写的。已逐字节核对：Marble 官方仓库全树 24 个文件，**不包含任何 `.html` 源码**——他们的交互式可视化（withmarble.com/curriculum）根本不公开。我们是看了那个公开网站之后自己实现的。

那么为什么还要专门致谢？

**因为是它让这个项目的缺口显形。**

2026 年 7 月，Marble 发布了一套美国 K-12 知识图谱：1,590 节点 / 3,221 边，交互式 3D 可视化做得很好看。同一时间，我们想找一套国内的中文教材知识图谱，找遍 GitHub 只有零散几个学生项目。

**一个像样的公开可视化都不存在**——这件事本身，比「缺一个可视化」严重得多。它说明的不是没人做，是做出来也没人看，看了也没人指出问题。

Marble 那套确实把可视化做得很好。但它 2026-07-08 发布之后再没推过任何一次 commit，5,478 star、924 fork，底下挂着 **18 条 open issue**——其中 #11 质疑 14 个主题名和内容对不上（实测 4 例确实对不上），#18 质疑依赖关系荒谬，唯一回复是有人说想认领去修。三个月了，没人动。

**所以本项目真正要证明的是：校验本身也需要被校验。** 一套图谱如果没人查，成环了没人知道，主题名和内容对不上也没人知道。

对照着做的过程中发现的东西，都记在 [`known-issues.md`](known-issues.md) 里——包括上游自己漏掉的两个环，以及我们自己的校验层出过的 bug。

## 怎么跑

需要 Python 3，零第三方依赖。

```bash
python3 src/normalize.py     # 原件 → data/normalized/graph.json
python3 src/validate.py      # → data/normalized/validation.json，有硬错误时 exit 1
python3 src/build_viz.py     # → viz/知识图谱3D.html
python3 src/health_check.py  # 上线体检：数据层 + 构建层 + 判别力自检（106 项）
```

上海版站点（数据已入库，直接重建即可）：

```bash
python3 src/shanghai_relocate_rjb.py  # → data/shanghai-rjb-positions.json（人教版节点的沪教位置）
python3 src/shanghai_graph.py   # → data/shanghai-graph.json
python3 src/build_shanghai.py    # → shanghai.html
```

> `shanghai_graph.py` 依赖 `shanghai-rjb-positions.json` ——
> 那是「人教版前置节点在沪教教材里的真实位置」表，
> 用来把站里混进来的人教版节点挡在门外（详见 README 第九节）。
> 改了沪教教材原文层就要重跑第一个脚本。

**视觉密度自查**（三个站的画布密度，用真浏览器量）：

```bash
node src/check_layout_density.mjs index.html shanghai.html kx.html
node src/measure_density.mjs index.html shanghai.html kx.html   # 只测量不判定
```

只想到成品页，直接 `open viz/知识图谱3D.html` 就行。

**注意 `validate.py` 现在会 exit 1**，这是对的——3 个环还在数据里。修得去改上游，已上报 [issue #8](https://github.com/haolpku/K12-KGraph/issues/8)。

|---|---|---|
| `data/lessons.jsonl` | 一页一条（教材的「课」），带章节、页码、提到的概念 | 12,939 页 |
| `data/concept-text.jsonl` | 一个概念一条，带**教材原话**（291 个概念有定义句） | 1,361 个概念 |
| `data/vision-pages.jsonl` | 一页一条，带**公式(LaTeX)** 和**图形语义** | 4,390 页 |
| `data/vision-pages-alt.jsonl` | 同上，**其他 8 个出版社**的教材 | 7,784 页 |

后两个是**视觉层**：教材扫描件的 PDF 文本层是坏的（公式字体的 ToUnicode 表缺失），
OCR 只能救回汉字，**公式和图形会全丢**。视觉层换成让多模态模型直接读渲染出来的页面，
把 `y = \frac{1}{2}(x-6)^2 + 3`、顶点 `(6, 3)`、图上的对称轴虚线这些东西捞回来。

都出现过，它们不是「这本书教这个概念」的证据。所以沪教这一侧用四个信号：
**目录**（教材自己写的目录，最硬的证据）、**目录近似**、**集中**
（在这本书里成片出现，且占它在全部 26 本沪教书里命中数的 1/3 以上）、
**同册**（人教图谱里的家 == 这本书的册次）。详见
[`known-issues.md` 的 ISSUE-40](known-issues.md)。

**公式和例题题干是页面原文，可以直接引用；图形描述是模型转述，引用时必须标「据图」。**
schema 和用法见 [`docs/agent-data.md`](docs/agent-data.md)。

### 册次排名原来算错过

原来册次排名用的是 `list(BOOKS)` 的插入顺序，于是物理的「九年级」（覆盖整个
初三学年的一本书）排在数学「九上」**之前**。单学科内看不出来，一引入跨学科边
就大面积误报。

现在册次映射抽在 `src/books.py`，三个概念分开：

| 字段 | 用途 | 口径 |
|---|---|---|
| `grade` | 画面分层（锥形高度） | 沿用既有口径，不动 |

### 为什么搜索不是加分项，是必需品

8,667 个点，**鼠标点在数学上**。这一页原本的设计是「拖一圈看看整体分布」，
好看，但解决不了任何人真正会问的问题：

> 「我家孩子卡在哪个知识点上，我想看看它得先会什么。」

那个问题靠鼠标永远问不出来。所以搜索框放在标题区下方，正对着读屏顺序，
`/` 一键聚焦，**跳过去的时候不只是选中——还会把相机解到那个点的正前方**，
否则选中了也不知道自己在哪。

匹配规则很简单，故意保持可解释：

| 关键词 | 匹配对象 | 优先级 |
|---|---|---|
| `小数` | 知识点名字开头 | 最高 |
| `乘法` | 知识点名字中间 | 次之 |
| `五上` | 册次（`dz` 字段，形如「五上·概念」） | 最后 |

同一档里按**被依赖度**（下游有多少知识点等着它）降序——那是更吃紧的知识点。
结果最多 8 条，`↑↓` 选、回车跳、`Esc` 取消。

**已知边界：不支持拼音首字母。** 本机没有可用的汉字转拼音工具（无 `uconv`、无
PyObjC），没有可靠来源就不硬凑一张 1,602 字的拼音表——**错的拼音表比没有更糟**，
打错字找不到东西，用户会以为是自己不会用。真要做，得引入一份权威汉字拼音表
再逐字校对，不是临时能补上的。

跨学科重名会如实并列显示。比如搜「光合作用」会同时出现两条：生物七上（初中）
和化学必修二（高中）——后者出现在必修二，是因为人教化学在「有机化合物」一节
从光合作用讲有机物的来源，定义也是化学口径。这是同一个概念在两本教材里都出现，
不是重复数据。

**结果数会写明是「按名字匹配」。** 搜「二次函数」返回 19 条——那是名字里含
「二次函数」的 19 个知识点横跨九上 15 条 / 必修一 3 条 / 选必一 1 条，
是**同一主题在不同册次的平行表述**，不是 19 个前置。
脚注原来写的是「共 19 条匹配」，那句话读起来就是「二次函数有 19 个前置」，
所以改成直接否掉这个读法：「共 19 条名字匹配，**不是 19 个前置**」。
**凡是「N 条结果」可能被读成「N 个关系」的场合，都得写清楚是哪种匹配。**

### 卡片上的六栏关系

点开一个知识点，卡片列六栏：

| 栏 | 数据来源 | 可点 |
|---|---|---|
| 要先会 / 学会后能学 | `prerequisites_for`（概念↔概念） | 是 |
| **教材顺序 · 上一单元 / 下一单元** | **节点 id 里的 `_chNN_sMM` + 册序** | **是** |
| 教材标为前置的章 | `leads_to`（章↔章）经 `appears_in` 上溯 | 否 |
| 更一般的概念 / 它的具体表述 | `is_a` | 是 |

加后四栏是因为**只画 `prerequisites_for` 会让人读错数据**。
实测上游 8,590 个知识点里 6,025 个（70.1%）没有 `prerequisites_for` 入边，
而真实先修往往记在章节上。比如「二次函数[九上]」概念层前置确实是 0，
但 `leads_to` 给出 5 章，其中有「第十九章 一次函数[八下]」「第二十一章 一元二次方程[九上]」。

所以**空态文案不能说「它是这一串的起点」**——那是拿数据缺口冒充知识点属性，
九上册的二次函数在常识上不可能是起点。现在写的是
「数据里没记前置 —— 不等于它没有前置」。详见 `known-issues.md` 的 ISSUE-06。

#### 教材顺序链：零新数据源

`leads_to` 只有 594 条，稀疏得没法当导航用。所以顺序链是**另算**的：

- 609 个 Section 全部带 `_chNN_sMM`，264 个 Chapter 带 `_chNN`
- 配上 `books.py` 已有的册序，**完整教学顺序就写在节点 id 里**
- 排成 **873 个单元**，**8,590 个知识点 100% 都能定位**（873 个里 712 个能点到具体知识点）

**这个顺序不是猜的，是核对过的。** `src/verify_order.py` 从
`TapXWorld/ChinaTextbook` 拉人教社官方教材 PDF，**只抽目录页**，
跟推导结果逐条比：

12 册小学数学全跑的结果：

```
次序错误 0 处（这才是「排错了」）
未核对 1 册：二上 —— 目录解析不全，不是「核对通过」
覆盖缺口 3 册共 4 个单元（图谱没建，不是排错）
```

- **11/12 册次序完全一致**，包括之前抽查过的数学九上、物理八下、化学必修一
- **二上未核对**：第 2 条单元名跨了三行，正则吃不下。脚本宁可报「未核对」
  也不报「核对通过」—— 误报会被看见，把没核对说成通过才是真的害人
- **覆盖缺口 4 处**：四上缺「亿有多大」，四下缺「数学广角—鸡兔同笼」和「总复习」，
  五下缺「总复习」。**教材里有、图谱没建**，所以顺序链会跳过它们

> **一处我以为数据错了、结果是我记错了**：小学数学一上的官方目录里
> 「认识图形（一）」确实排在「6~10 的认识和加减法」之前。我按旧版教材的
> 印象以为反了，拉 2022 年 8 月第 2 版官方 PDF 一对 —— 是对的。
> 这就是为什么顺序链要有一份独立来源来对：**读数据不等于读事实**。

**顺序 ≠ 先修。** 教材把 A 排在 B 前面，不等于学 B 必须先会 A。
所以这一栏的文案严格叫「上一单元 / 下一单元」，提示行也写着「是教材排列顺序，不是先修」。
把顺序说成先修，跟把「没标」说成「没有」是同一类错误。

**能不能让模型重建这套先修关系？** 实测过，结论写在 `docs/probe-llm-prereq.md`：
独立子代理盲测 10 个知识点给出 22 条前置，**按名字跟已有边 0 条重合**，
但逐条人工判定 **22/22 语义站得住、0 条说错**，其中 17 条是数据漏标的纯增量。
根因不是模型不准，是**两套数据的词汇表对不上** —— 上游的先修边指向
「面积转化方法」这种**方法**节点，模型指向「平行四边形的面积」这种**知识**节点。
**结论：不能直接并入，必须先有概念层。**

**PDF 只用来核对，不入库也不抽正文。** 每页都印着
「版权所有·未经许可不得采用任何方式擅自复制或使用本产品任何部分·违者必究」，
缓存目录 `data/pdf-cache/` 已在 `.gitignore` 里。

### 九之三、学习卡：让人能靠这个图谱自学

> **提的人**：2026-10-25，一位朋友看见这个项目后很兴奋，想拿它来自学术理化。
> **他说的原话**：「用一套数据库，然后让每个知识点都可以对应召回这个知识图谱里节点对应的那个内容」。

现在这个项目是个**图**：能查「谁是谁的前置」「教材第几页有这个概念」。
但它**不能回答「我要学这个概念，读什么、做什么题、先补哪个」**——
对着图谱自学的人现在的路径是：打开网页 → 搜一个词 → 看它挂了多少条前置 →
点开前置 → 再搜 → 再点前置……

**图能告诉你顺序，不能给你教材。**

所以加了 `data/learn-cards.jsonl`：**一个概念一张卡，六个面**。

```
浮力（八下）
├─ 这是什么   教材定义句（原文照抄）+ 图谱定义（转述，标来源）
├─ 怎么算     教材原书上的公式 + 图形语义（标「据图」）
├─ 练一练     教材例题题干
├─ 先补这些   直接前置（跟站点「学习路径」面板同源）
├─ 在书里     哪本书 · 哪一章 · 第几页
└─ 读这段     教材原页上的那段话
```

**每一段都带来源标记。** 教材原话是「教材自己说的」，
图谱定义是「数据集转述的」—— 混起来就是在拿二手货冒充一手。
详细口径见 `docs/agent-data.md`，需求和验收判据见 `docs/需求清单.md` R-1。
| 面 | 覆盖 | 说明 |
|---|---|---|
| `what` | 93.1% | 三级证据强度：教材定义句 4.0% / 教材提及句 10.2% / 图谱定义 92.4% |
| `how` | 22.3% | 教材原书上的公式 + 图形语义 |
| `practice` | 20.7% | 教材例题题干 |
| `prereq` | 95.0% | 直接前置，**不设限量**（跟站点口径一致） |
| `where` | 100% | 哪本书哪一章哪几页 |
| `read` | 32.2% | **教材原页上的那段话** |

**四个实测定位的问题（已修）：**

1. **前置链跟站点对不上** —— 原来只读 `graph.json` 的上游边（3,703 条），
   而站点用的是「上游边 + 自建边（13,461 条）合并过环检测」的结果，
   「浮力」的前置是空的（站点上明明有 3 个）。
   → 改成**直接读站点已构建好的 payload**，不可能对不上。
2. **例题一条都召不回来** —— 视觉层的例题字段叫 `stem`，不叫 `text`，
   按 `text` 取了 8,590 个空。
3. **教材原话答非所问** —— 「电阻」召回的是「内电阻」「电阻率」「电阻箱」。
   引文确实带 `definition` 标记，但**定义的对象不是这个概念**。
   → 改成按「定义对象 == 概念名（且独立成词）」筛，分三级证据强度。
4. **图/公式噪声** —— 视觉层的图描述带 `tier` 分级：
   `topical` = 这一页在讲这个概念；`broad` = 只有模型转述里提到概念名，
   页面本身跟它没关系。`broad` 的一律不要。

**「先补这些」跟站点面板逐条一致，这条是跑真浏览器验的** ——
在 Chrome 里加载站点页面、调它自己的 `pathRows()`，把输出跟学习卡逐条比。
自己重算一遍不算验证（那是两份实现，迟早对不上）。

### 九之四、（可选）向量检索：用自己的话问教材

> **这一层是可选的 —— 装它不影响主项目的任何功能。**
>
> 主项目是**静态站点 + jsonl 数据层**：双击 `index.html` 就能玩，
> agent 直接读 `data/learn-cards.jsonl` 就能用，**不需要任何第三方依赖**。
>
> 这一层给「**用我自己的话说这个概念**」用的 ——
> 上游概念名大量是改写过的（「ATP（能量储存形式）」「DNA（遗传信息载体）」），
> 教材里根本不这么写，**精确字面匹配只覆盖 4.6%**。
> 学习卡解决不了这个（它按概念名查），向量检索能。

**代价说清楚**（实测）：

| | |
|---|---|
| 装依赖 | `pip install -r optional/milvus/requirements.txt`（**需要 Python ≥ 3.10**） |
| 下模型 | `ollama pull bge-m3`（1.2 GB，**教材不出境**） |
| 灌库 | **45 分钟**（5.5 万段教材） |
| 库大小 | 375 MB（**不入库**，是派生产物） |
| 换来 | 「用自己的话问」这个能力 + 按字段筛选查询 |

**这是取舍，不是免费午餐** —— 想清楚再装。

> **提的人**：2026-10-25，朋友是 **Milvus 生态负责人**，要拿这个项目来自学术理化。

三张表：

| 表 | 是什么 | 粒度 | 条数 |
|---|---|---|---|
| `kg_textbook` | 教材原文**段落** | 一段 | 55,242 |
| `kg_concept` | 知识点 | 一个概念 | 8,590 |
| `kg_prereq` | 先修边 | 一条边 | 17,164 |


**没有直接上 Milvus，先按它自己的方法论评估**：
Milvus 官方 workshop 那份 `15-retrieval-tier-selection.md` 自己写着
「从阶梯顶端起步是**教学选择，不是工程默认**」，
而且它实测的结论是 **T0→T1（词法 + 查询改写）带来全部质量增益，T2（向量）相对 T1 是 0**。

我们自己的实测（12 个「BM25 找不到定义句」的真实概念）：

| 方案 | 结果 |
|---|---|
| 纯 BM25 | 5/5 命中 |
| 纯语义（`nomic-embed-text`，本机 274 MB） | **0/15** —— 英文模型，「邻补角」召回「近似数」 |
| 纯语义（`qwen3-embedding:8b`，本机 4.7 GB） | 4/4 正确项排第一，但 10 秒/条 → 全量 37 小时 |
| 纯语义（**`bge-m3`**，本机 1.2 GB） | 5/5 正确项在 top-2，**0.05 秒/条** → 全量 45 分钟 |

**选 `bge-m3`**：中文质量够、速度够、本机跑得动、**教材不出境**
（教材有版权，嵌入全在本机算完，只把向量存本地）。

⚠️ **版权页不进库**：教材前十几页是版权页 / 编者信息
（「版权所有…未经许可不得另做他用」「美术编辑：…」）。
这些页进向量库 = 检索时召回版权声明，
而且**把教材版权信息复制进了数据库** ——
项目一直守着「教材 PDF 不入库、只存抽出来的结构化事实」这条线，不能在这儿破。

⚠️ **段落边界不能切在词中间** —— 按句末标点切。

**第一次用**：看 [`docs/milvus-上手.md`](docs/milvus-上手.md) ——
起库、查询、两条要注意的，都在那一页里。

其中四项不是测搜索，是测**页面自己有没有说谎**——这四条全是被真抓出来的，
不是预防性写的：

- **标题里的数字**：模板 `<title>` 原来写死「1,590 个知识点」，那是 Marble 的规模，
  我们是 8,667。已经推上线才发现。现在标题走占位符，测试比对 payload 里的真实节点数。
- **无外部资源请求**：页面原来从 `fonts.googleapis.com` 拉字体。**那个域名在中国
  大陆是被墙的**——一页给中国学生看的中文页面，引它等于给主要用户埋雷。现已全部去掉，
  改用系统字体栈（PingFang SC / 微软雅黑 / Noto CJK）。
- **标题字形指纹**：去掉字体后标题悄悄变成了宋体。字宽量不出来（CJK 全角，一律相同），
  所以改用像素指纹——同一句话分别按 `sans-serif` 和 `serif` 渲染比对灰度。
  实测两者指纹不同，h1 现在与 `sans-serif` 一致。
- **跨学段抽检 7 个节点**（小学数学 → 高中理化）：逐个搜、回车，然后采样画面正中的像素。
  焦点节点画成「白心 + `#ff3d7f` 洋红环」，`flyTo` 解出的相机角度保证它的投影落在
  `(W/2, H/2)`，所以**「有没有飞准」是可证伪的**。实测 7/7 命中。

> 还有一份把模板函数切片出来跑的 node 测试，已经删掉：它 5 项失败全是脚手架自己的错
> （`n.x/n.y/n.z` 是运行时算的，payload 里没有），切片拼装的测试改一次模板就可能测
> 一个不存在的东西，比没有测试更危险。

## 边界

- **图谱本身还是只有人教版，且是六三制。** 10,685 个节点 id 里 100% 是 `rjb`，
  画布上的 8,667 个点一个其他版本的都没有。

  **这对不同地区的学生影响很大。** 以上海为例：小学数学全市统一使用**沪教上海版**，
  且上海是**五四制**（小学 5 年 + 初中 4 年），本图谱是六三制（小学 6 年）。
  逐条对过五年级上册，核心计算内容（小数乘除法、简易方程、平行四边形/三角形/梯形面积）
  两边都有，但章节结构和若干专题不同——
  沪教版独有平均数、组合图形的面积、连乘乘加乘减；
  人教版独有位置（数对）、可能性、植树问题。

  **结论：能当参考用，不能当教材索引用。** 查「五年级要学哪些知识点」大方向没问题，
  查「第几章第几节」会错，查版本独有的专题会查不到。

  > **但现在多了一层缓解**：跨版本对照把 304 个概念**在别的版本里落在哪一节**标出来了
  > （`data/alt-align.json`，卡片底部可见「其他版本教材里的位置」）。
  > 这解决的是「这个概念在沪科版里第几节」，
  > **解决不了**「沪科版独有的专题本图谱里压根没有」。

- **扩版本在数据源上是可行的，而且已经动手了。** 源仓库 `TapXWorld/ChinaTextbook` 里初中数学有
  沪科技版、浙教版、湘教版、苏科版，小学有冀教版、北师大版、苏教版等。
  本项目的归一化层与校验层**与版本无关**，换一套教材 PDF 就能再跑一遍，
  校验报告格式不变。目前已拉 **9 个出版社 51 本（895 MB）**，
  跨版本对照覆盖 7 个册次、304 个概念；其他版本的视觉层 **45 册 7,784 页 / 100%** 跑完
  （覆盖清单见 `data/vision-cover-alt.json`）。
  **上海学生用的沪教版（上海教育出版社）仍然没有教材文件**——仓库里只有沪科版
  （上海科学技术出版社），是另一套教材。
  但**它的官方册次结构已经查清并入库**（上海市教委《教学用书目录》，见 ISSUE-38），
  电子版在国家中小学智慧教育平台上、**需要登录**才能翻页。
- **只覆盖理化生数。** 语文、英语、道德与法治、历史、地理不在上游数据里。
- **只覆盖中国。** 跟 Marble 那套美英图谱（1,590 节点）不是一套东西，册次和学段对不上，不能直接叠在一起比。
- **数据是 2026 年 5 月的教材快照。** 教材改版不会自动跟上，且上游没标注是哪一版（见上）。
  我们手上的教材全是 **2024 改版之前**那一代；人教七下 2024 新版所有章号整体 +2。
